# C1: integer sharing gaps

Implemented all three requested declaration paths. No commits, pushes, model calls, or verification-rule changes.

## Implementation

1. **Concurrent multiplier lanes.** A homogeneous group containing multiple binary integer/fixed-point multiplier lanes from one mode is normalized to `twin_precision_subword` before family resolution. The returned VAR declaration records this selection and removes the superseded family's pins. The existing gated partial-product matrix and lane-cut carry reduction compute every lane concurrently, including signed full products and `mul_high`; this is not time multiplexing. Across-mode groups retain the existing selected-family sharing mechanism. Fixed/restricted family bindings remain binding.
2. **Adder + comparator + PG logic.** Partition validation composes the supported binary lane-local mechanisms: each comparator/PG logic consumer must have its lane's adder. A triple's declaration is normalized to `subtractor_comparator` with the actual adder family and pins. The comparator drives subtraction through the same PG/CPA and reads carry/equality, with either `sum_or_tree` or `operand_xnor`; it has no separate comparator instance. Fidelity witnesses identify the actual shared lane module. Other integer lanes and modes can participate under the existing partitioned-adder geometry/family constraints.
3. **Automatic PG fusion.** Explicit partitions now merge each PG logic group's connected adder group transitively, retaining their other supported members. The merged partition still undergoes physical-sharing validation. Replanning checks the realized membership/family decisions before retaining a parent's unit, so a newly fused unit cannot accidentally restore stale parent RTL.

The candidate reproductions also exposed PG + `partitioned_carry_chain`, formerly refused in `alu_int`. Each lane now generates shared `p = a ^ b` and `g = a & b`, feeds `p` and the lane-local `g << 1` into the partitioned adder, and includes its high generate bit in its own carry-out. Dual unary result sets retain their own PG adder. Single-mode shared multiplier/adder selectors now use a constant instead of referencing an absent `mode` port.

## Remaining refusals and scope

- A same-mode multiplier group whose fixed/search domain excludes `twin_precision_subword` refuses with the required family variable named. Nonbinary encodings do not get this binary-array promotion. A lane width that does not divide the input word width refuses with both widths and a request to use independent lane multipliers. Direct low-level family selections remain strict; promotion is in the declaration/plan renderer, where the returned VARs can reflect it.
- A direct low-level triple with a conflicting comparator family/CPA/pin selection refuses; the declaration renderer normalizes searchable selections and refuses conflicting fixed bindings. An end-around-carry adder is still not a binary PG CPA.
- Unsupported kinds, missing/duplicate/unknown members, incompatible geometries, and incompatible adder families in a single partitioned word remain subject to the existing strict checks. Automatic PG fusion does not make arbitrary shifters, dividers, or unrelated structures shareable.
- Composition added here concerns the supported binary integer adder/comparator/PG mechanisms; it does not add new floating-point or nonbinary mixed-kind mechanisms.
