# C4: declaration robustness

Implemented in the working tree; no commits, pushes, model calls, or shared ADIR edits.

## Changes

1. **Boolean spellings.** VAR values and plan pins accept `True`, `False`, `true`, and `false`, either bare or surrounded by matching single/double quotes. Conversion is domain-aware and produces actual Python booleans before the renderer tests them. Boolean search subsets remain restricted: spelling normalization does not admit an excluded value. Numbers, `yes/no`, malformed quotes, and arbitrary strings are not coerced. ALU, dot, and SFU templates now all normalize declaration spellings; ALU and non-ALU family resolution also normalize direct overrides.
2. **Inactive candidate choices.** ALU resolution drops candidate choices whose variable-tree ancestor is closed, or whose selected family explicitly identifies that pin/child subtree as inactive. It records each ignored VAR name and its reason. This covers fused FMA closing separate adders, stored subnormal decode closing LZC/shifter children, and nested inactive parameters. Fixed YAML choices still refuse: those are instance contracts, not candidate slips. Unknown names are not classified as inactive.
3. **Other harmless slips found in the refusal audit.** Matching quotes around an otherwise valid enum/family member are removed only when the original spelling is invalid and the unquoted member belongs to that domain. The same inactive-choice projection handles carry-save/RNS shared-exit aliases, including parameters that only Harris topology reads. Incompatible *active* aliases still refuse. Group-family checks use canonical, active values too.

The renderer returns canonical active VARs, so ignored decisions do not survive into the new declaration. Default-valued explicit plan choices are checked for inactivity before their usual omission from the exported VAR block. Repairs that change only the declaration preserve the candidate's RTL edits, including edits to its top module.

### Notes and feedback

`families_of()` returns a dict-compatible result with `ignored` and `notes`. `plan_seed()` and `replan()` retain their tuple protocols and expose `.notes`; tuple unpacking and pickling are tested. Generated text includes `// chiALU declaration: ignored VAR ...: inactive (...)` comments. These survive ADIR's current seed/replan assembly and are visible in candidate source. Declaration normalization recovers those comments and attaches `.notes` to its result.

**Shared ADIR integration remains a documented patch, per the task's instruction not to edit ADIR.** Its current declaration check discards successful normalization notes, and its evaluator only forwards configured feedback fields. To put the notes into the candidate's feedback automatically, apply these exact changes to the shared ADIR source:

```diff
--- a/adir/declaration.py
+++ b/adir/declaration.py
@@
     outputs["detail"] = ("; ".join(problems) if problems
                          else f"declaration ok ({len(decl.vars)} declared, {len(defaulted)} at defaults{moved})")
+    outputs["notes"] = list(getattr(decl, "notes", ()))
+    if outputs["notes"]:
+        outputs["detail"] += "; " + "; ".join(outputs["notes"])
     return outputs

@@
         if v is not None:
             fb[e.text] = v
+    if decl_out.get("notes"):
+        fb[f"{instance.decl_node}.detail"] = decl_out["detail"]
     if runner.gave_up:
```

The declaration portion was exercised by compiling that function in memory, without changing shared files: the real ALU binding returned `ok=True` and detail naming the ignored `core.fp_adder.m0.family` and its `classic_fma` controller. No ADIR parser change is needed for chiALU: ADIR already invokes the template normalizer before its domain checks. Keeping this conversion in the domain-aware hook also preserves string-valued enums that legitimately contain `True`.

## Refusals deliberately retained

The audit captured 474 `ValueError`/`SelectionError` raise sites in `chialu/targets/rtl` and `chialu/plans.py` (snapshot: `.scratch/refusal_audit.txt`). No blanket exception-and-retry or catch-and-default behavior was added. These categories still refuse:

- Unknown structure selectors, slots, pins, or families; invalid values and domain exclusions. Their intended replacement is ambiguous.
- Fixed inactive YAML decisions and conflicting active shared-exit aliases: accepting them would contradict the instance or claim incompatible settings for one physical unit.
- Illegal partitions: incompatible kinds/formats, simultaneously active lanes sharing one datapath, unsupported same-mode/cross-mode sharing, or missing members.
- Missing library implementations, unreachable modules, rejected geometry, and mismatched requested/instantiated parameters. Selection/fidelity checks remain intact.
- Ineffective physical geometry, such as an oversized chunk or unavailable skip/prefix levels. These are not merely closed variable-tree branches, and silently changing them would misrepresent the requested architecture.
- Inexact behavior under exact contracts: bounded alignment, unsupported rounding/normalization arrangements, stochastic/full-window limitations, or approximate algorithms without their required contract.
- Insufficient RNS capacity, non-coprime moduli, incompatible reverse-converter geometry, unsupported representations, and incompatible fused/shared rounders.
- Dot/SFU architecture-specific inactivity and geometry refusals remain strict; this task's inactive-choice projection is for ALU declarations. Their boolean/enum spellings are normalized.
