# C3: reference microarchitectures are searchable

Implemented without changing the baseline RTL or weakening conformance. HardFloat and FPnew are now declarations of `targets/eval/fp_alu_cmp.yaml`, and both reproduce the requested synthesis points.

## Changes and root cause

1. **ADIR enumerated materialized branches, not the whole search space.** `Bindings.bind_defaults()` intentionally opens only the default families. `Instance.variable_order()` and `searched()` previously enumerated that dictionary. Reading `space` expanded the whole tree only for numeric backends, making coverage depend on the backend and earlier lookups. `Instance.variables` now materializes the complete indexed tree once when enumeration is requested; `variable_order`, `searched`, and `space` share that view. Grid, SMAC and NSGA-II obtain their bindings through `searched()`. Wildcard precedence and existing family/choice conditions are retained.

2. **Ancestor activity must be transitive.** Sampling, pruning and declaration checking now keep descendants inactive when an ancestor is inactive, including when an intermediate variable is fixed. A rejected/inactive explicitly declared parent cannot activate its children. The existing behavior-rules selftest's miniature instance was missing `core.family`; its fixture now supplies that ancestor, retaining the original assertion that the forbidden SR member is rejected with its rule's reason.

3. **`x_form` was fixed-only and lost outside `core.*`.** ALU permits fixed or searched `x_form`; the float comparison targets, plans target, numeric targets and their checked-in calibrated/no-LLM derivatives search it. `exact` remains the default. Elaboration checks every admitted X form against the target's option rules. Plans carry it in `options`, archive-to-plan conversion preserves it, and rendering reads it from the candidate. Changing only `x_form` refreshes the units. Surrogate features and the generated NSGA-II evaluator input carry it through training and prediction. The target generator preserves the new setting when files are regenerated.

The two reference YAMLs have no other non-core implementation option differing from the plain target. All 63 HardFloat core choices plus `x_form`, and all 54 FPnew core choices plus `x_form`, are representable. The previously missing two-path controls and `far_align`, `near_lz`, and `close_norm` subtrees are present, including their nested choices.

## Remaining refusals and limits

- No reference binding remains unreachable. The integer target retains fixed `x_form=exact`; compact X is a float implementation choice.
- Compact X with float conversion operations or stochastic rounding still refuses, with the existing `no_cvt_in_float_modes` / `no_sr` explanation. Search bindings containing an illegal form refuse at elaboration; callers can narrow to `exact`.
- Existing renderer restrictions remain: for example compact X with an unnormalized separate multiplier, exact-X-only fused rounding/bridge mechanisms, unrealized family pins and incompatible sharing plans. Search enumeration exposes the full declared conditional tree; it does not assert that every Cartesian combination is renderable. Candidate-dependent restrictions involving both X form and family choices still rely on renderer validation where existing member conditions cannot express them.
- This change does not fit a new surrogate or rerun an optimization campaign. The enlarged variable set and X-form features require a newly trained model for useful predictions; old models cannot price unseen feature values reliably.
