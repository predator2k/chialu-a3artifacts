# C5: numeric space / generator consistency

The original census gaps have been constrained at variable compilation or in the numeric target configuration; the repair loop has not been changed. An additional integration audit found that a **fully expanded C3 variable tree still has unsupported nested geometry combinations**, so that part of the requested whole-space objective remains incomplete. Do not interpret the current census as proof that the entire expanded tree is covered.

## Changes

- Family-local domains: compile the member domains of a union choice into `member_when`, including the disjoint LZD / priority-encoder `output_form` enums. Remove holes introduced when sparse integer ranges are unioned. ADIR now accepts conditions on every enum member only when their conditions cover every parent value that opens the variable.
- Activity: `ALU_ACTIVITY_RULES` is the shared source for renderer rejection and ADIR `inactive_when` clauses. This covers stored-subnormal unpacker LZC/shifter slots, incrementer topology, Harris parameters, EAC branches, blocked-adder choices/slots, and the bridge-FMA subnormal representation. `inactive_when` is a disjunction of conjunctions, expands indexed sibling names, orders dependencies, and is honored by random sampling, numeric pruning (including NSGA-II), and declaration checking. No renderer checks were relaxed.
- Geometry: narrow ripple chunk search domains to the lane, exponent, significand, or count-adder widths. Exclude recursive Karatsuba for three-bit significands, FPGA carry chains for small count results, and the two-bit count / selectable CLA intergroup combination. Root lane EAC is available only for ones' complement formats; nested binary-CPA adapters retain their EAC families.
- Numeric target configurations: independently sampled rounder/unpacker families omit `shared_across_formats`; the sharing plans still select it in the full RTL target. The scheme-independent multiplier search omits internally fused rounding, which cannot feed the existing shared unrounded multiplier interface. FMA sharing remains dedicated per mode. Integer independent logic selection omits PG fusion, which requires a corresponding physical adder/logic partition. These changes are also in `targets/make_targets.py`.
- LZA: constrain `positive_result_only` to the swapped datapath in this space. This is conservative: a dual-string unswapped implementation can also use it, but the current single-sibling member condition does not express that alternative.
- Generator bug discovered during full evaluation: FP component multipliers now use `FAM.mul_module`'s existing binary wrapper. The former special case instantiated a twin-precision matrix with an undriven `sel`; the wrapper ties the single packing selector to zero. The failing FP and HF candidates both passed lint, bit-exact conformance, and synthesis after the fix.

## Remaining limitations

A separate audit materialized **all** variables before sampling (10,389 integer, 25,109 FP, and 24,208 HF variables, versus the current initially materialized 99 / 295 / 249). After the activity changes, this still finds unsupported nested geometry combinations: blocked-adder chunk sizes larger than their blocks, recursive lookahead levels that cannot exist at the actual width, counter final adders with too few real groups, multiplier component combinations, and operation-specific multiplier families. These points continue to refuse; the generator has not been made permissive. The final expanded-tree audit rendered 9/30 integer, 7/30 FP, and 8/30 HF points without repair. Its log and full error records are `expanded-final.log` and `integration.json`. C3 integration requires additional geometry-dependent domains; the near-100% objective for that fully expanded space is not achieved by this change.

Explicit cross-format sharing with incompatible pins or too few selected formats still refuses. An internally rounded multiplier still cannot be placed in the shared unrounded multiplier interface. Invalid explicit inactive pins, unsupported geometry, and non-ones'-complement root EAC declarations still refuse. Numeric sampling excludes the listed unsupported combinations before a declaration is drawn.

Regenerate previously calibrated numeric YAML copies from the updated primary numeric files before reusing them; historical run declarations and generated calibration copies were not rewritten.

The existing sharing-plan conversion can replace grouped members' independent choices with the group's selection/defaults. This work does not alter `plan_of` or `scheme_repair`, so absence of `realize` drops alone is not a proof of equality between every independent numeric feature and every grouped physical pin.
