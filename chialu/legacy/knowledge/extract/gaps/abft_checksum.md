# abft_checksum: proposed changes to the space

* `checksum` values or a `checksum_dimension: {spatial, temporal, both, filter_only, input_only, filter_and_input}` choice and an `encoding_scope: {row, column, full}` choice — the neural-network and convolution schemes are named by which operand dimension is summed, which decides storage/transport coverage and online work, and the matrix algorithms distinguish row, column and full encodings [hari_2022, ozen_2020, ozen_2025, jou_abraham_1986]
* choice `checksum_arithmetic: {ordinary_numeric, modulo_2r, widened_full_precision, residue}` with an `integer_overflow_handling: {widened_checksum, tuple_of_int8_filters, modular_with_coverage_loss}` refinement — integer checksums use modulus 2^r or widened accumulators, residue arithmetic bounds word length at the cost of rare aliasing, and the representation chosen decides whether equality is exact [huang_abraham_1984, jou_abraham_1986, ozen_2019, hari_2022]
* choice `comparison_policy: {exact, tolerance, layer_profiled_threshold, trained_deviation_threshold}` — floating-point round-off perturbs the invariant, so the comparison rule is a design decision with false-alarm consequences [huang_abraham_1984, ozen_2019, ozen_2020, ozen_2025]
* choices `weight_sequence: powers_of_two` and a code-distance parameter — the weight sequence sets detection/correction capability and whether the checks are shift-implementable [jou_abraham_1986]
* choice `protected_operation: {addition, multiplication, scalar_product, lu_decomposition, transposition, inversion, convolution}` — the encoded algorithm decides which relations are preserved [huang_abraham_1984, hari_2022]
* choice `module_error_confinement: {elementwise_mesh, rotated_submatrix, systolic_diagonal, scheduled_output_partition}` — processor assignment and scheduling decide whether one faulty module's errors can mask each other or stay correctable [huang_abraham_1984, jou_abraham_1986]
* choice `task_fusion: {unfused, fused_ocg, fused_iocg}` — whether the convolution/epilog kernels also generate output or input-and-output checksums changes data movement and coverage under `placement: software` [hari_2022]
* `placement` multi-value convention, or a value for the combined form — several designs are supplied in both software and array-edge forms, and the array-edge form specifically means an embedded extra systolic column plus edge accumulation/check logic [ozen_2019, ozen_2020]
* choice `invariant_embedding: {sanity_neuron_filter, additive_inverse_input, both}` — whether the invariant is embedded as extra parameters, an appended temporal input, or both [ozen_2025]
* `correction` extended to a `recovery_mode: {none, weighted_checksum_correction, replay, spare_mac_replacement, staged_multischeme}` choice — the surveyed recovery modes are more than a Bool [ozen_2025]
