## summary
The chapter defines an application-specific floating-point accumulator that keeps the running sum in a fixed-point window, which removes alignment/normalization shifts from the recurrence and permits exact or bounded-error accumulation. A partial carry-save variant divides carry propagation into configurable chunks for higher frequency. An exact multiplier followed by this accumulator forms an accurate sum-of-products operator.

## families
### streaming_accurate_accumulator  (role: proposes)
mechanism: Each floating-point summand is shifted once into an application-specific fixed-point window and converted from sign/magnitude to two’s complement without carry propagation. The recurrent operation is fixed-point addition without in-loop normalization. MSBA bounds overflow, LSBA controls accuracy/area, and MaxMSBX limits the input-shifter range. Sticky bits report input overflow/input underflow/accumulator overflow. A separate LongAcc2FP component performs carry propagation, leading-zero/one counting, shifting, sign conversion, and rounding when a floating-point result is required.
choices:
  approach: shifted_fixed_point_window   # p.138
  window_bits: 63   # p.144
  in_loop_normalization: false   # p.138
new_choices:
  msb_position: MSBA — upper fixed-point position chosen to prevent accumulator overflow   # p.140
  lsb_position: LSBA — lower fixed-point position controlling accumulation error and area   # p.140
  maximum_summand_msb: MaxMSBX — bounds the input-shifter range independently of MSBA   # p.140
  post_normalization: software | shared_pipelined | replicated_low_frequency | dedicated_pipelined — selects how LongAcc results become floating-point   # p.141
slots:
  cpa: fpga_carry_chain [prefix_over_chain=false]   # p.138
parameters: wE/wF summand fields; wA = MSBA − LSBA + 1 as used in the case study; 63-bit case-study accumulator; accumulators expected rarely to exceed 100 bits   # p.140, p.144

conditions: The fixed-point window benefits applications whose result/summand magnitude bounds can be estimated or profiled. MaxMSBX=MSBA remains safe when the summand bound is unknown, while a smaller MaxMSBX reduces shifter area. LongAcc2FP may be omitted for final-only results or shared when normalization is needed once per N accumulations.   # p.140, p.141, p.143

### kulisch_long_accumulator  (role: extends)
mechanism: Exact, unnormalized products are shifted into a long fixed-point accumulator and rounded only after accumulation. A product of two 1+wF-bit significands supplies a 2+2wF-bit significand without multiplier rounding. The application-specific exponent and term-count bounds reduce the accumulator from the generic DP width of 4288 bits to about 100-200 bits, while the input shifter becomes twice as large.
choices:
  accumulator_width_bits: 4288   # p.145
  organization: monolithic   # p.145
  carry_resolution: immediate   # p.145
new_choices:
  product_input: exact_unnormalized — accumulates every bit of each significand product   # p.145
  application_specific_width: 100-200 bits — replaces a format-wide generic accumulator with bounded application sizing   # p.146
slots:
  cpa: fpga_carry_chain [prefix_over_chain=false]   # p.138
parameters: generic DP accumulator 4288 bits; FPGA application-specific accumulator 100-200 bits; product significand 2+2wF bits; at least 100,000 products in [0,1] in the synthesis comparison   # p.145, p.146

### kulisch_long_accumulator  (role: analyzes)
mechanism: A partial carry-save accumulator partitions the carry chain into k-bit chunks separated by registers. The recurrence contains only a k-bit carry propagation. Standard notation is recovered either by injecting zeros for enough cycles after accumulation or by an external pipelined carry-propagation stage before normalization.
choices:
  organization: segmented_lazy_carry   # p.140
  carry_resolution: periodic_sweep   # p.140
new_choices:
  carry_chunk_bits: k — determines recurrent carry-chain length and target frequency   # p.140
  redundant_exit: zero_flush | pipelined_propagation — selects latency-only or hardware conversion from the partial carry-save representation   # p.140
slots:
  cpa: fpga_carry_chain [chain_segment_length=32]   # p.140
parameters: k=1 gives standard carry-save; k=4 is illustrated; k=32 reaches 400MHz; zero flushing takes floor((MSBA−LSBA)/k) cycles; pipelined propagation takes ceil(wA/k) levels   # p.140, p.141
results:
| metric | value | unit | technology / device | baseline | condition | page |
| frequency/register overhead | 400 / 1/32 more | MHz / registers | Virtex-4 and StratixII | immediate full-width carry propagation | k=32 | p.140 |
| illustrated register overhead | 1/4 more | registers | abstract | immediate full-width carry propagation | k=4 | p.140 |
errors_and_checks: The redundant representation is exact; conversion requires carry propagation rather than approximation.   # p.140
conditions: Smaller k supports a higher target frequency but increases register overhead. Zero flushing costs no hardware when only the final value is needed, while pipelined propagation supports access to the running value.   # p.140
evidence: Sections 10.1.3-10.1.4; Figures 10.3 and 10.5.
