## summary
The document analyzes the Intel Pentium floating-point division defect in a radix-4 SRT divider whose quotient-digit lookup table omits five active entries. The document characterizes the resulting errors, measures their operand-dependent frequency, and presents a software workaround that rescales at-risk operands before division.

## families
### srt_high_radix  (role: analyzes)
mechanism: The Pentium divider generates radix-4 quotient digits from {-2, -1, 0, +1, +2} while retaining the partial remainder in carry-save form. A two-dimensional Programmable Lookup Array selects each digit from four divisor fraction bits and seven leading bits of the carry-save remainder. The last active entry in five divisor columns is absent, so zero is selected instead of +2; the next radix multiplication overflows the remainder register and prevents recovery. (pp.20-24)

errors_and_checks: The largest demonstrated ratio error leaves only 14 accurate bits. The residual error is a power of two except for the first defective divisor column, where it is three times a power of two. Tests found 1,738 errors exceeding single-precision accuracy, 7,863 exceeding double-precision accuracy, and 9,915 exceeding extended-precision accuracy among the tested single-precision pairs. The paper estimates approximately 10,490 errors after accounting for unobserved late-cycle cases. (pp.21, 24-25)
conditions: The exponent does not participate in the defect, so power-of-two scaling has no significant effect. An at-risk divisor must begin with one of five specified 11-bit patterns, but an error also requires a dividend that produces the missing remainder-table address. The quoted random error rates assume uniformly distributed mantissas and exclude underflow/overflow. Correlated decimal-derived operands can raise the error rate by more than eight orders of magnitude. The faulty circuitry also affects remainder, tangent, and arctangent instructions. (pp.20, 23-27)

### sig_div_then_round  (role: analyzes)
mechanism: The Pentium floating-point divide instructions use the defective radix-4 SRT significand divider across single-, double-, and extended-precision formats. A software workaround tests the denominator before division and multiplies both operands exactly by 15/16 when the denominator is at risk. Single- and double-precision operands are temporarily handled in extended precision so the rescaled quotient rounds to the same result that a defect-free chip would produce. (pp.19, 28-29)

errors_and_checks: The denominator test provides an a priori safety check rather than detecting a bad residual after division. For an at-risk denominator, exact scaling by 15/16 moves the denominator outside the unsafe region. The software FPATAN replacement lacks internal hardware guard bits, so its extended-precision result can differ by up to 3 ULPs. (pp.28-29)
conditions: The FDIV workaround requires inspection of the denominator bit pattern and special handling for denormal operands. Source-level function calls add calling-sequence overhead and some C compilers cannot preserve the distinction between double and extended precision, so in-line assembly is preferred for correctly rounded results. Few technical computations place division in the inner loop, according to the authors. (pp.29-30)
evidence: “The software workaround” (pp.28-30); Figure 5 (p.29)

## space_gaps
* `srt_high_radix` lacks a `residual_form` choice, although the document identifies carry-save partial-remainder representation as part of the selection path. (p.22)
* `qds_table` appears as a component-slot target but has no declared family; this document exposes divisor-index width, remainder-index width, column count, physical implementation, and active-entry completeness as relevant choices. (pp.22-23)
* The vocabulary has no field for a quotient-digit table implementation defect or completeness check, although five omitted active entries determine the reported behavior. (p.23)

## open_questions
* The document does not report the Pentium fabrication technology node.
* The document gives the quotient digit set {-2, -1, 0, +1, +2} but does not classify it as minimal, intermediate, or maximal redundancy.
* The double- and extended-precision error counts are extrapolated from single-precision observations rather than exhaustively measured. (p.24)
