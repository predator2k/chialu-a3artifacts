## summary
The paper proposes a fully parallel IEEE 754-2008 decimal floating-point unit for ±(A×B)±C with one terminal rounding. The unit supports decimal64/decimal128 DPD operands and selectable standalone multiplication/addition/subtraction. The combinational design can be partitioned into four pipeline stages with one result available each clock cycle.

## families
### decimal_fma  (role: proposes)
mechanism: The significand path aligns C within a 4p-digit width while generating signed-digit-recoded partial products in parallel. A CSA tree merges the middle 2p digits of C with the partial products, and a decimal CPA produces a 2p-digit intermediate result. Two leading-zero-digit counters guide result alignment. The rounder selects either the p-digit truncated result or its incremented value before DPD result encoding.

### parallel_decimal_multiplication  (role: instantiates)
mechanism: Multiples of the multiplicand are selected from each multiplier digit through signed-digit recoding, so all partial products are generated in parallel. A CSA tree reduces the partial products together with the middle 2p digits of the aligned addend to Sum and Carry vectors. A fast decimal CPA then produces the 2p-digit intermediate result.

## space_gaps
* `decimal_fma` lacks choices or a slot for its terminal rounding mechanism, although this design selects between a truncated result and its incremented value under seven rounding directions.   # p.532
* `parallel_decimal_multiplication.slot final_adder` permits only binary adder families, while this design specifies a fast decimal CPA.   # p.530
* `parallel_decimal_multiplication.multiplier_recoding` lacks a generic signed-digit value for documents that do not disclose the digit set.   # p.530

## open_questions
* The paper does not identify the signed-digit recoding digit set or the internal digit encoding used by the CSA tree.
* The paper does not identify the architecture of the fast decimal CPA.
* The paper does not state whether the ASIC synthesis results apply to decimal64, decimal128, or both.
