## summary
The document proposes Double MAC, which packs two exact multiply-and-accumulate operations with a shared unsigned operand into one unmodified FPGA DSP block. The implementation doubles MAC-array capacity at equal DSP usage and improves measured CNN performance by 14% for AlexNet and 84% for VGG on a Xilinx Virtex-7 485T. Shift-only per-layer scaling limits the recognition-quality loss from 8-bit quantization.

## families
### dsp48_style_slice  (role: extends)
mechanism: A DSP48E1 slice uses its 25x18-bit multiplier and 48-bit accumulator as a virtual 2-way SIMD MAC. Two n-bit operands are packed into one multiplier input with at least n separating bits, while both products share the other n-bit operand. A guard bit detects lower-lane carry-outs. A counter and correction accumulator retain carry/sign corrections until a final external subtraction. The FPGA fabric itself is unchanged, but LUTs/FFs implement correction logic.

errors_and_checks: The MAC array is exact for the quantized operands, with no internal truncation or rounding. The guard bit detects lower-word carry-out, an α-bit counter records carry events, and a separate accumulator records signed-multiply correction terms. Accuracy loss comes only from input-feature/weight/bias quantization.   # p.3–p.6
conditions: The two products must share one operand, and the common operand must be unsigned. Two packed n-bit products require an output at least 4n bits wide and at least n separating bits. Signed data operands require a delayed correction. The design requires extra LUTs/FFs and applies only where shared operands can be found, such as paired CNN output channels or neighboring spatial outputs.   # p.2–p.5

### integer_mac  (role: instantiates)
mechanism: The CNN engine forms a pipelined array of Double MAC units. Each unit updates two independent output accumulations while sharing an input activation, so the array pairs output feature maps in M-N-parallel convolution. Signed input feature maps are converted to unsigned values by flipping the MSB and adjusting each output-channel bias offline. Per-layer power-of-two scaling expands the utilized 8-bit range without runtime multipliers.

## new_families
### shared_operand_packed_dsp_mac  (domain: dsp: FPGA DSP blocks, closest: dsp48_style_slice, why_not: dsp48_style_slice describes the hard block, while this mechanism creates virtual multiplier lanes through operand packing/correction without changing the block)
mechanism: Two n-bit products A×C and B×C are formed by packing A and B into one wide DSP multiplier operand and sharing C. Unsigned products require lane spacing and carry extraction. Signed-unsigned products interpret the packed input through a signed multiply and correct the lower lane when B is negative. Carry-out/sign corrections accumulate separately and are merged after the MAC sequence.

## space_gaps
* `dsp48_style_slice` needs a multiplier-packing choice and a slot that can name `shared_operand_packed_dsp_mac`; the current `simd_partition` choice does not distinguish native ALU SIMD from virtual packed multiplication.   # p.1–p.4
* `integer_mac` needs a shared-operand/lane-pairing choice because the performance depends on pairing output channels or spatial positions around one common operand.   # p.4–p.5
* The multiplier slot domains lack a family for an exact shared-operand packed multiplication implemented through one hard DSP multiplier.   # p.3–p.4

## open_questions
* The paper does not identify the internal multiplier/adder microarchitectures of DSP48E1, so the corresponding component slots remain `UNKNOWN`.
* The paper gives graphical relative-quality results for individual bit widths but prints only the “less than 1%” result for 8-bit quantization.
