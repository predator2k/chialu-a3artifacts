## summary
The document proposes the first hardware adder/subtractor for IEEE P754 decimal64 operands whose significands use Binary Integer Decimal encoding. The design provides all five rounding modes, partitions operations into three cases, and uses variable latency plus a shared 64-bit multiplier to reduce area. Exceptions, NaNs, and infinities are excluded. # p.288, p.290, p.294-p.295

## new_families
### bid_decimal_fp_addition  (domain: decimal: decimal misc, closest: decimal_fp_addition, why_not: `decimal_fp_addition` assumes DPD-stored/BCD-computed significands, while this design aligns and rounds BID significands as binary integers. # p.288-p.290)
mechanism: The adder swaps operands so `ANexp ≥ BNexp`, computes `K = |Aexp-Bexp|`, and counts the decimal digits `Qa` of `ANc`. Cases are selected from `Qa+K` and whether `K=0`. Cases 1 and 2 align with multiplication by `10^K`, add/subtract binary significands, and round if needed. Case 3 first rounds `BNc`, pushes `ANc` toward 16-digit precision with `10^g`, and then adds/subtracts. Rare overflow/cancellation cases feed the result through the rounder again or recalculate alignment. One multiplier is shared between alignment and rounding. # p.290-p.294

### binary_integer_decimal_digit_counter  (domain: shift: bit counting, closest: lzd_cell_tree, why_not: `lzd_cell_tree` returns a leading-zero/leading-one position, while this component converts that position into an exact decimal-digit count. # p.291)
mechanism: A binary leading-1 detector produces the most-significant-bit position `m`. One LUT maps `m` to the minimum possible decimal-digit count `n`, which can underestimate by at most one. A second LUT supplies the smallest `10^n` greater than `2^m`. Comparing the input `x` with `10^n` selects `n` or `n+1`, producing the exact number of decimal digits for an unsigned binary integer. # p.291

## space_gaps
* `decimal_fp_addition` needs a BID significand/alignment option because its present alignment domain covers only decimal-significand shifters. # p.288-p.290
* Decimal floating-point families need a `decimal_digit_counter` component slot for BID alignment/rounding control. # p.290-p.291
* A BID-adder family needs choices for case partitioning, multiplier reuse, variable latency, and rare-case recovery. # p.290-p.294

## open_questions
* The total latency of results requiring a second rounding pass or alignment recalculation is not reported. # p.294
* The internal microarchitecture of the synthesized 64-bit multiplier is not reported. # p.294
* The synthesis results are preliminary, and the document does not report power, clock frequency, initiation interval, or post-layout measurements. # p.294
