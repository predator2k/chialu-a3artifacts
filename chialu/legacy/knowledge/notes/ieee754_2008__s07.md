## summary
This clause fixes five exception classes, their triggers, their default non-stop results, and their status-flag behavior. It also specifies overflow results by rounding direction and binary/decimal tininess detection for underflow.

## other_normative
* Five kinds of exceptions shall be signaled when they arise, and the implementation shall provide a corresponding status flag for each kind. # p.47
* Default non-stop handling delivers a default result, continues execution, and raises the corresponding status flag except for exact underflow. # p.47
* Status flags shall be lowered only at the user’s request. The user shall be able to test/alter flags individually or collectively and save/restore all flags at one time. # p.47
* A program that does not inherit status flags begins execution with all status flags lowered. # p.47
* Language standards should specify defaults for flag existence outside explicit use, asynchronous flag effects, non-programmatic visibility, propagation between invoking/invoked functions, and optional persistence/inheritance. # p.47
* One invocation of an operation required by this standard signals at most one exception directly. Default handling can additionally signal inexact for overflow or inexact underflow. # p.47
* restoreFlags or raiseFlags may directly raise any combination of status flags. Any other standard operation under default handling may raise at most overflow with inexact or underflow with inexact. # p.47
* Nonstandard operations should signal exceptions according to the standard-operation definitions, but exceptions for nonstandard functions are language-defined. # p.47
* A quiet NaN delivered for invalid operation should provide diagnostic information. # p.48
* The implementer shall choose before-rounding or after-rounding tininess detection for binary formats and shall use the chosen method consistently for all radix-two operations, including conversions under a binary rounding attribute. # p.49
* Decimal formats shall detect tininess before rounding. # p.49
* The selected tininess-detection method does not affect the rounded underflow result. # p.49

## model_gaps
* The model has no exception signals/status flags, so it cannot reproduce flag raising, clearing, testing, saving/restoring, inheritance, or the unobservable exact-underflow signal. These gaps do not change the delivered numeric result. # p.47–49
* The model has one NaN without signaling/quiet distinction, so it cannot reproduce signaling-NaN invalid-operation triggers or the implementation-defined fusedMultiplyAdd case involving a quiet NaN. This gap can change exception behavior and NaN selection. # p.48
* The model does not represent diagnostic NaN information, so it cannot check the recommendation that an invalid-operation NaN provide diagnostic information. This gap may affect the exact NaN encoding. # p.48
* The model lacks roundTiesToAway, so it cannot represent that rounding-direction attribute. Within this clause, its specified overflow result is nevertheless the same signed infinity as roundTiesToEven. # p.48
* The model represents binary rather than decimal floating-point formats, so it cannot check mandatory before-rounding tininess detection for decimal formats. This gap affects decimal exception behavior rather than supported binary results. # p.49

## open_questions
* The implementation must select before-rounding or after-rounding tininess detection for binary formats; the clause does not select one. # p.49
* The implementation must define whether fusedMultiplyAdd(0, ∞, c) or fusedMultiplyAdd(∞, 0, c) signals invalid operation when c is a quiet NaN. # p.48
* This clause does not state the default non-floating result for invalid floating-point-to-integer conversion or integer-format logB; the referenced operation clauses must supply it. # p.48
