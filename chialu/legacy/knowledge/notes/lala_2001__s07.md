## summary
The chapter classifies fault tolerance by hardware/information/time/software redundancy and by backward/forward recovery. It defines duplication-based masking/detection and repeated execution with rollback, while showing that voters/checkers, coverage, checkpoint placement, and reconfiguration determine the resulting reliability.   # p.178, p.179, p.204, p.206-p.208

## families
### duplication  (role: taxonomizes)
mechanism: Two identical modules form a duplex system whose outputs are continuously compared; a mismatch indicates a fault and initiates diagnosis or reconfiguration. Three identical modules form TMR, where a voter masks one disagreeing output immediately. NMR generalizes voting to N modules, and triplicated TMR replicates the voter/module pair to avoid a single voter failure.
choices:
  replication: 2 or 3   # p.179-p.180, p.188
  comparison_point: per_cycle   # p.185, p.188
  temporal_stagger: false   # p.185, p.188
new_choices:
  decision_mechanism: {majority_vote, output_match} — majority voting masks an error, while matching detects disagreement   # p.179-p.180, p.188
  post_fault_mode: {remain_replicated, simplex, replace_with_spare} — the system may continue with voting, discard a module, or reconfigure   # p.183, p.185, p.188
slots:
  comparator: UNKNOWN   # p.188
parameters: TMR uses 3 modules; NMR tolerates up to n = (N - 1)/2 module failures; the space-shuttle example uses N = 4   # p.180
results:
| metric | value | unit | technology / device | baseline | condition | page |
| reliability | R_TMR = 3R_m^2 - 2R_m^3 | probability | abstract | one module | independent module failures; perfect voter | p.180 |
| reliability | R_TMR = 0.5 | probability | abstract | R_m = 0.5 | no reliability improvement | p.181 |
| MTBF | 5/6λ | time | abstract | simplex MTBF = 1/λ | exponential module reliability | p.181 |
| fault tolerance | (N - 1)/2 | module failures | abstract | simplex | N is odd | p.180 |
| masking latency | immediate | qualitative | abstract | fault detection followed by recovery | temporary or permanent module fault | p.185 |
errors_and_checks: Disagreement detectors compare each TMR module output with the voter output; a duplex matching circuit detects mismatch but cannot initially distinguish a module fault from a matching-circuit fault.   # p.185, p.188
conditions: TMR improves mission-time reliability only when redundancy is applied to sufficiently reliable modules. A voter failure defeats basic TMR, and voter failure rate λ_v > λ makes the redundant system less reliable than the original system for all t. Common-clock synchronization also requires a fault-tolerant clock.   # p.181-p.182, p.185
evidence: Sections 6.1.1-6.1.2; Figures 6.1-6.6; Equations 6.1-6.3.

### time_redundancy  (role: defines)
mechanism: Time redundancy repeats instructions/program segments/programs or rolls execution back to a saved checkpoint after fault detection. Alternating logic executes a function and its self-dual successively, producing a true output in one period and the complementary output in the next.
choices:
  transform: self_dual [outside domain]   # p.204
  iterations: 2   # p.204-p.205
  shift_distance: UNKNOWN   # p.204
  correction: true   # p.204
new_choices:
  repetition_scope: {instruction, program_segment, entire_program} — the scope restored and reexecuted after detection   # p.204
  checkpoint_policy: {periodic, strategically_inserted} — checkpoint frequency trades normal execution time against rollback time   # p.204, p.213
slots:
  comparator: UNKNOWN   # p.204-p.205
parameters: alternating logic requires 2 time periods per verified output; rollback resumes from the latest valid checkpoint   # p.204-p.205, p.213
results:
| metric | value | unit | technology / device | baseline | condition | page |
| verified-output time | twice as much time | time | abstract | unverified function execution | alternating logic | p.205 |
| hardware increase | generally modest | qualitative | abstract | duplex space redundancy | alternating logic | p.205 |
errors_and_checks: Reexecution recovers from temporary faults; repeated detection after retry indicates a permanent fault requiring another recovery method. Duplicate checkpoint storage protects checkpoint creation, while singular events must not be repeated.   # p.204
conditions: More checkpoints increase normal computation time, while wider checkpoint spacing increases recovery/reexecution time. Alternating logic is unsuitable when time is a major factor.   # p.204-p.205, p.213
evidence: Section 6.3; Sections 6.5.3-6.5.4; Figures 6.17-6.18.

## new_families
### standby_reconfiguration  (domain: checker: concurrent error detection, closest: duplication, why_not: only one module may operate and arbitrary spare counts exceed duplication's replicated lockstep structure)
mechanism: An active module is replaced by a cold or hot spare after periodic testing, self-checking logic, or a watchdog detects a fault. Retry distinguishes temporary from permanent faults before reconfiguration; successful replacement is self-repair.
choices: standby: {cold, hot}; detection: {periodic_test, self_checking, watchdog_timer}; retry: Bool; spares: Int[1..N]
results:
| metric | value | unit | technology / device | baseline | condition | page |
| reliability | R = 1 - (1 - R_m)^(S+1) | probability | abstract | simplex | S spares; perfect detection and switchover | p.186 |
| best spare count | five or fewer | spares | abstract | UNKNOWN | mission time below one-tenth of simplex mean-life | p.186 |
evidence: p.185-p.188

### hybrid_modular_standby  (domain: checker: concurrent error detection, closest: duplication, why_not: a voted N-module core and dynamically switched spares are jointly required)
mechanism: A voted TMR/NMR core masks faults while disagreement detectors identify a failed core module and a switching network substitutes a spare. The system continues as standard TMR after all spares are exhausted.
choices: core_modules: Int[3..N]; spares: Int[0..S]; switch: {rotary_iterative_cell}; retry: Bool
results:
| metric | value | unit | technology / device | baseline | condition | page |
| simultaneous core-fault tolerance | floor((N - 1)/2) | failed modules | abstract | TMR | hybrid (N, S) | p.189-p.190 |
evidence: p.189-p.192

### error_correcting_information_redundancy  (domain: checker: concurrent error detection, closest: rns_redundant, why_not: Hamming/Hsiao/parity codes protect state and memory rather than arithmetic residue channels)
mechanism: Redundant check bits or coded state assignments identify and correct errors. State-machine assignments use minimum Hamming distance 3 for single-error correction; memory systems regenerate check bits, form a syndrome, and correct the identified bit.
choices: application: {state_machine, memory}; code: {hamming, hsiao, majority_logic_decodable, horizontal_vertical_parity}; multierror_extension: {chip_spares, orthogonal_latin_square_address_skew}; periodic_checking: Bool
results:
| metric | value | unit | technology / device | baseline | condition | page |
| minimum Hamming distance | 3 | code distance | abstract | uncoded state assignment | single-bit detection and correction | p.193 |
| correction capability | single-bit error | errors per word | abstract | unprotected memory | SEC/DED memory | p.196, p.198 |
evidence: p.193-p.203

## space_gaps
* duplication needs `decision_mechanism: {majority_vote, output_match}` because the chapter distinguishes masking TMR from detecting duplex comparison.   # p.179-p.180, p.188
* duplication needs NMR replication counts above 3 and explicit standby-spare composition.   # p.180, p.186, p.189
* time_redundancy needs `self_dual` and untransformed retry values in `transform`.   # p.204
* time_redundancy needs checkpoint placement/storage and repetition-scope choices.   # p.204, p.213

## open_questions
* The chapter does not establish whether its voters, disagreement detectors, or duplex matching circuits satisfy the `two_rail_tree` slot contract.
* The registry must decide whether checkpoint rollback belongs inside arithmetic-unit `time_redundancy` or remains a system-level recovery mechanism.
