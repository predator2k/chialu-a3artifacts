## summary
I-BERT performs Transformer inference without floating-point arithmetic by combining INT8 MatMul/Embedding, INT32 accumulation/nonlinear kernels, and INT8 requantization. Integer quadratic approximations implement GELU and Softmax, while an exact integer square-root recurrence implements LayerNorm. RoBERTa-Base/Large retain baseline-level GLUE accuracy and obtain 2.42−4.00× speedup against FP32 on a Tesla T4 GPU.

## families

Algorithm 2 evaluates the polynomial and GELU scaling with integer arithmetic. Static scaling constants are precomputed, so inference contains no floating-point calculation. # p.5-p.6

### softmax_layernorm  (role: proposes)
mechanism: I-Softmax subtracts xmax, decomposes each nonpositive input as x̃ = (−ln 2)z + p, approximates exp(p) with a quadratic on p ∈ (−ln 2, 0], and implements 2−z by right shift. LayerNorm computes dynamic mean/variance in integers and obtains the standard deviation through an exact integer square-root recurrence. # p.6-p.8
choices:
  exp_evaluation: integer_polynomial   # p.7
  max_subtraction: true   # p.7
  layernorm_support: true   # p.7-p.8
new_choices:
  exp_range_reduction: subtract_max_then_ln2_decompose — bounds the polynomial input to (−ln 2, 0]   # p.7
  layernorm_sqrt: integer_newton_recurrence — computes floor square root using division/addition/shift   # p.8
slots: none
parameters: exp polynomial degree 2; L(p) = 0.3585(p + 1.353)^2 + 0.344; nonlinear kernels INT32; square root converges within at most four iterations for INT32 inputs   # p.7-p.8
results:

## new_families
### integer_newton_sqrt  (domain: sfu: elementary-function units, closest: newton_raphson, why_not: the existing family specifies seed-table fixed-step refinement, while this recurrence returns an exact integer floor with data-dependent termination and up to four iterations)
mechanism: Starting from x0 = 2^ceil(Bits(n)/2), the recurrence xi+1 = floor((xi + floor(n/xi))/2) repeats until xi+1 ≥ xi and returns xi. Each iteration uses one integer division, one integer addition, and one bit shift. # p.8
choices: input_width: {int32}; result_contract: {floor_exact}; termination: {monotone_non_decrease}
results:

| convergence bound | at most four | iterations | UNKNOWN / 2021 | none | any INT32 input | p.8 |
evidence: §3.6, Algorithm 4

## space_gaps
* transformer_activation_lut.operand_format lacks int32, which is the precision used for I-BERT nonlinear kernels. # p.8, p.15
* transformer_activation_lut.calibration lacks interpolating-point/L2 coefficient fitting. # p.4-p.7
* range_reduction.method lacks the ln 2 quotient/remainder reduction used by i-exp. # p.7
* softmax_layernorm lacks a square-root implementation choice or slot for the exact integer recurrence. # p.8

## open_questions
* Algorithm 3 specifies qexp/sum(qexp) but does not identify the integer divider microarchitecture. # p.7
* The polynomial kernels do not report absolute latency, area, energy, integer word lengths for intermediates, or overflow margins. # p.5-p.9
* The LayerNorm division/square implementations are described only as straightforward integer arithmetic. # p.8
* Table 3 does not separate speedup from MatMul, GELU, Softmax, and LayerNorm. # p.9
