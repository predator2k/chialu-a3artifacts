## summary
The paper presents an IEEE-754R decimal floating-point square-root unit based on reciprocal-square-root approximation and modified Newton-Raphson iteration. The design combines a DPD-encoded lookup table, operand modification, a reused sequential decimal multiplier, and remainder-based rounding. The synthesized decimal64 implementation reports a 0.95 ns critical path and maximum latency of 210 clock cycles.

## families
### decimal_newton  (role: proposes)
mechanism: A piecewise-linear seed approximates 1/√X, after which each modified Newton-Raphson iteration computes Ri+1 = Ri/2 × (3 − X × Ri²) with three decimal multiplications, a 9's complement, and reduce-by-half logic. Directed intermediate rounding keeps Ri below 1/√X. The unit then computes a preliminary root and uses X − Q² to select a correctly rounded result. # pp.2-5

### operand_modification_multiply  (role: extends)
mechanism: X is split into k-digit XM and lower part XL. A first-order Taylor expansion around A = XM + 2/3 × 10^−k is rearranged as R0 = C′ × X′, so one stored coefficient and one decimal multiplication generate the reciprocal-square-root seed. X′ is formed in parallel with the table lookup, and its trailing 10^−n−1 term is ignored to avoid carry propagation. # pp.2-3

  input_bits: 10   # p.3; k = 3 DPD index
  function: recip_sqrt   # p.2
new_choices:
  coefficient_encoding: DPD — XM indexes the table in DPD and C′ is stored in DPD   # pp.3,5
  expansion_point: XM + 2/3 × 10^−k — the shifted Taylor point improves the seed by one digit over expansion at XM   # pp.2-3
slots:
  none
parameters: k = 3 decimal index digits; C′ is 7 decimal digits; X′ operand modification; one lookup and one decimal multiplication   # pp.3,5

## space_gaps
* `decimal_newton` needs an iteration-multiplier component slot because the sequential/multi-digit/parallel decimal multiplier choice determines latency and dominates 74% of the reported core area. # pp.5-7
* `operand_modification_multiply` needs decimal-digit index/coefficient widths because its `input_bits`/`output_bits` choices do not directly express the paper's k-digit DPD table. # pp.3,5
* `operand_modification_multiply` needs coefficient-encoding and expansion-point choices to represent the DPD table and A = XM + 2/3 × 10^−k optimization. # pp.2-3

## open_questions
* The 160770 um² core area excludes the lookup table, while the only cited ROM area is for a generic 3KB ROM in 0.18 micron technology; the document does not provide a same-technology total area. # p.5
* The paper references an extended version for the complete odd-exponent equations and rounding optimizations, so those details are not established by this document. # pp.2,4
