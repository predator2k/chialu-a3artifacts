## summary
The paper proposes table-based hardware algorithms for division, logarithm, reciprocal square root, exponential, ATAN2, and sine/cosine in IEEE 754 double precision. The algorithms use truncated fixed-point rectangular multiplications, table lookups, residual refinement, and terminal Taylor corrections to achieve relative error within 0.5 ulp. A unified implementation uses two rectangular-multiplier groups, two table/adder groups, and a full-precision multiplication complex.

## new_families
### rectangular_multiplier  (domain: mul: integer multipliers, closest: truncated_fixed_width, why_not: `truncated_fixed_width` does not represent an asymmetric n × m multiplier whose short operand removes partial-product rows.)
mechanism: The fixed-point rectangular multiplier multiplies an n-bit operand by an m-bit operand with m < n and truncates the result without rounding. The assumed 56 × 16 implementation uses recoding, an eight-operand Wallace tree, and 72-bit carry assimilation; most algorithms need only 56 × 12. Additional addends can enter the Wallace tree for multiply/add polynomial evaluation. # pp.278-279, 284, 288

### table_residual_refinement_sfu  (domain: sfu: elementary-function units, closest: lut_plus_poly, why_not: the algorithms iteratively multiply table-derived chunks and propagate truncation residuals rather than evaluate one table-selected local polynomial.)
mechanism: Each function decomposes its operand or residual into short chunks addressed into tables. Rectangular multiplications apply table-derived factors while the remaining error is propagated to another refinement stage. A table lookup or truncated Taylor series terminates the refinement when the residual is small. Logarithm reuses reciprocal partial results; reciprocal square root applies half-sized correction factors; exponential subtracts logarithms of truncated exponential factors; ATAN2 and complex exponential use complex rotations formed from truncated components. # pp.279-287
choices:
  function_set: {division, logarithm, reciprocal_square_root, exponential, atan2, sine_cosine} — supported operations # pp.279-287
  residual_chunk_bits: {8, 9, 10, 11} — extracted correction widths used by the algorithms # pp.279-287
  terminal_correction: {table_square, truncated_taylor} — final residual treatment # pp.280-287
  rectangular_multiplier_count: {1, 2} — peak specialized-multiplier requirement depends on the function # pp.282-287

## space_gaps
* The multiplier vocabulary lacks asymmetric operand widths and truncation width as first-class choices for rectangular multipliers. # pp.278-279
* The SFU vocabulary lacks a residual-refinement family that composes multiple table-derived multiplicative corrections before a terminal Taylor correction. # pp.279-287
* The SFU vocabulary lacks a slot for a rectangular multiplier that accepts extra carry-save addends during polynomial evaluation. # pp.284, 288
* The shared multi-function hardware choice is absent from the elementary-function families. # p.288

## open_questions
* Table II's per-function table-size entries are not legible in the supplied text, so only the textual aggregate memory values are recorded.
* The paper proves relative error within 0.5 ulp but does not state that every result is correctly rounded under all IEEE rounding modes.
* General trigonometric range reduction is assigned to software using cited methods; the paper evaluates hardware only after reduction to [0, π/2). # p.287
