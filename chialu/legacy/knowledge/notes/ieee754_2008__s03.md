## summary
This clause defines binary/decimal floating-point data, interchange encodings, and format parameters. It also defines conformance requirements and recommended extended/extendable formats.

## other_normative
* **Required:** A supported format shall provide initialization and conversions to/from every other supported format. A supported arithmetic format shall provide every Clause 5 operation. A supported interchange format shall provide means to read/write its specified encoding. # p.17
* **Required:** A programming environment conforms for a radix by implementing one or more basic formats of that radix as both arithmetic and interchange formats. Format support is language-defined or implementation-defined when the language is silent or defers the choice. # p.17
* **Required:** The format parameters are b = 2 or 10, precision p, emax, and emin, where “emin shall be 1 − emax for all formats.” # p.18
* **Required:** Each format represents signed zero; finite values `(−1)^s × b^e × m` with `emin ≤ e ≤ emax` and `m = d0 • d1d2…dp−1`; +∞/−∞; and qNaN/sNaN. These are the only represented floating-point data. # p.19
* **Required:** The equivalent integer-significand representation is `(−1)^s × b^q × c`, where `emin ≤ q + p − 1 ≤ emax`, `0 ≤ c < b^p`, `e = q + p − 1`, and `m = c × b^(1−p)`. # p.19
* **Required:** The smallest positive normal value is `b^emin`; the largest finite value is `b^emax × (b − b^(1−p))`; and every finite value is an integral multiple of `b^emin × b^(1−p)`. Nonzero values below `b^emin` are subnormal and have fewer than p significant digits. # p.19
* **Required:** Every format has distinct +0/−0 representations. Binary interchange formats have one representation for each signed zero, while decimal formats have many. # p.19
* **Required:** A binary interchange encoding is `S | E | T`: S is 1 bit, E is a w-bit biased exponent `E = e + bias`, and T is a `t = p − 1` bit trailing significand. # p.20
* **Required:** Binary E values 1 through `2^w − 2` encode normals, E = 0 encodes zeros/subnormals, and E = `2^w − 1` encodes infinities/NaNs. # p.20
* **Required:** Binary decoding is: E = `2^w − 1`, T ≠ 0 gives qNaN/sNaN; E = `2^w − 1`, T = 0 gives `(−1)^S × (+∞)`; `1 ≤ E ≤ 2^w − 2` gives `(−1)^S × 2^(E−bias) × (1 + 2^(1−p) × T)`; E = 0, T ≠ 0 gives `(−1)^S × 2^emin × (2^(1−p) × T)`; and E = 0, T = 0 gives `(−1)^S × (+0)`. # p.20
* **Informative:** For binary k = 64 or a multiple of 32 with k ≥ 128: `k = 1 + w + t = w + p`; `w = k − p = round(4 × log2(k)) − 13`; `t = p − 1 = k − round(4 × log2(k)) + 12`; `p = k − round(4 × log2(k)) + 13`; `emax = bias = 2^(w−1) − 1`; and `emin = 2 − 2^(w−1)`. # p.20
* **Required:** Decimal representations of the same value form a cohort. Decimal operations select both the numerical result and a cohort member according to 5.2. # p.21
* **Required:** A decimal interchange encoding is `S | G | T`: S is 1 bit, G is a `w + 5` bit combination field, E is the `w + 2` bit quantity `q + bias`, T contains `J × 10` bits, and `p = 3 × J + 1` decimal digits. # p.21
* **Required:** Decimal G0 through G4 = 11111 encodes NaN regardless of S. G5 = 1 selects sNaN and G5 = 0 selects qNaN. T is the payload, whose maximum is `10^(3×J) − 1`; canonical NaNs have G6 through Gw+4 = 0 and a canonical payload. # p.21, p.22
* **Required:** Decimal G0 through G4 = 11110 encodes `(−1)^S × (+∞)`. Canonical infinities have G5 through Gw+4 = 0 and T = 0. # p.22
* **Required:** A decimal finite value is `(−1)^S × 10^(E−bias) × C`, where C combines the leading significand from G with T. # p.22
* **Required:** In decimal significand encoding, G patterns 110xx/1110x encode `d0 = 8 + G4` and leading exponent bits `2G2 + G3`; patterns 0xxxx/10xxx encode `d0 = 4G2 + 2G3 + G4` and leading exponent bits `2G0 + G1`. # p.22
* **Required:** Decimal-encoded T contains J densely-packed-decimal declets. Computational operations produce only the 1000 canonical declets and accept the 24 non-canonical declets. # p.22
* **Required:** In binary significand encoding, G0G1 = 00/01/10 makes E equal G0 through Gw+1 and makes the remaining bits the significand. If G0G1 = 11 and G2G3 = 00/01/10, E is G2 through Gw+3 and the significand is `8 + Gw+4` prefixed to T. # p.22
* **Required:** The maximum binary-encoded significand is `10^(3×J+1) − 1`, or `10^(3×J) − 1` for a NaN payload. A larger encoding is non-canonical and is interpreted as c = 0. Operations always accept non-canonical significands. # p.22
* **Informative:** For decimal k divisible by 32: `k = 1 + 5 + w + t`; `w = k / 16 + 4`; `t = 15 × k / 16 − 10`; `p = 9 × k / 32 − 2`; `emax = 3 × 2^(w−1)`; `emin = 1 − emax`; and `bias = emax + p − 2`. # p.22
* **Required:** DPD decoding maps `b(6),b(7),b(8),b(3),b(4) = 0xxxx` to `d(1) = 4b(0)+2b(1)+b(2)`, `d(2) = 4b(3)+2b(4)+b(5)`, `d(3) = 4b(7)+2b(8)+b(9)`. # p.23
* **Required:** DPD decoding maps `100xx` to `4b(0)+2b(1)+b(2)`, `4b(3)+2b(4)+b(5)`, `8+b(9)`. # p.23
* **Required:** DPD decoding maps `101xx` to `4b(0)+2b(1)+b(2)`, `8+b(5)`, `4b(3)+2b(4)+b(9)`. # p.23
* **Required:** DPD decoding maps `110xx` to `8+b(2)`, `4b(3)+2b(4)+b(5)`, `4b(0)+2b(1)+b(9)`. # p.23
* **Required:** DPD decoding maps `11100` to `8+b(2)`, `8+b(5)`, `4b(0)+2b(1)+b(9)`. # p.23
* **Required:** DPD decoding maps `11101` to `8+b(2)`, `4b(0)+2b(1)+b(5)`, `8+b(9)`. # p.23
* **Required:** DPD decoding maps `11110` to `4b(0)+2b(1)+b(2)`, `8+b(5)`, `8+b(9)`. # p.23
* **Required:** DPD decoding maps `11111` to `8+b(2)`, `8+b(5)`, `8+b(9)`. All 1024 bit patterns shall be accepted. # p.23
* **Required:** DPD encoding maps leading digit bits `000` to `b(0:2)=d(1,1:3)`, `b(3:5)=d(2,1:3)`, `b(6)=0`, `b(7:9)=d(3,1:3)`. # p.23
* **Required:** DPD encoding maps `001` to `d(1,1:3)`, `d(2,1:3)`, `1`, `0,0,d(3,3)`. # p.23
* **Required:** DPD encoding maps `010` to `d(1,1:3)`, `d(3,1:2),d(2,3)`, `1`, `0,1,d(3,3)`. # p.23
* **Required:** DPD encoding maps `011` to `d(1,1:3)`, `1,0,d(2,3)`, `1`, `1,1,d(3,3)`. # p.23
* **Required:** DPD encoding maps `100` to `d(3,1:2),d(1,3)`, `d(2,1:3)`, `1`, `1,0,d(3,3)`. # p.23
* **Required:** DPD encoding maps `101` to `d(2,1:2),d(1,3)`, `0,1,d(2,3)`, `1`, `1,1,d(3,3)`. # p.23
* **Required:** DPD encoding maps `110` to `d(3,1:2),d(1,3)`, `0,0,d(2,3)`, `1`, `1,1,d(3,3)`. # p.23
* **Required:** DPD encoding maps `111` to `0,0,d(1,3)`, `1,1,d(2,3)`, `1`, `1,1,d(3,3)`. Computational operations generate only these 1000 canonical patterns. # p.23
* **Required:** The 24 patterns `01x11x111x`, `10x11x111x`, and `11x11x111x` are not generated by computational operations, but they are accepted and decode to values from 0 through 999. # p.23
* **Required:** Binary interchange widths are 16/32/64/128 and every multiple of 32 at least 128. Decimal interchange widths are every multiple of 32 at least 32. Same-size interchange is exact without overflow/underflow. # p.24
* **Recommended:** Extended/extendable formats extend arithmetic precision. If provided, they shall represent all data defined by b/p/emax and provide every Clause 5 operation. # p.25
* **Recommended:** Extended/extendable encodings should be fixed width. Any such encoding is implementation-defined and may match an interchange format. # p.25
* **Recommended:** Language standards should define extendable-precision mechanisms for each supported radix. # p.25
* **Required:** A language standard supporting extendable precision shall permit specification of p/emax and specification by p alone. For p alone, emax shall be at least `1000 × p` when p ≥ 237 bits for binary or p ≥ 51 digits for decimal. # p.25
* **Recommended:** A language standard or implementation should support an extended format for the widest supported basic format in each radix. # p.25
* **Informative:** The smallest binary interchange width supporting at least p ≥ 113 bits is `k = 32 × ceiling((p + round(4 × log2(p + round(4 × log2(p)) − 13)) − 13) / 32)`. The decimal formula is `k = 32 × ceiling((p + 2) / 9)` for p ≥ 1. # p.25

## model_gaps
* The model has no decimal floating-point format, DPD/BID significand encoding, decimal cohorts, or non-canonical decimal encodings. This gap affects decimal bit-exact values and interchange encodings. # p.21-p.24
* The model has one NaN without qNaN/sNaN distinction or payloads. This gap affects bit-exact NaN encodings and can affect later NaN propagation. # p.18, p.20-p.23
* The tuple model does not retain multiple representations of one decimal value or multiple signed-zero encodings. This gap affects bit-exact decimal interchange but not the decoded numerical value. # p.19, p.21
* Implementation-defined extended/extendable encodings are not represented by the fixed binary-float tuple. This gap affects interchange bits when such formats are supported. # p.25

## open_questions
* The supported basic/interchange formats must be obtained from the language or implementation; the clause does not select them. # p.17
* A decimal implementation’s choice between decimal and binary significand encoding must be specified externally. # p.22
* Extended/extendable format encodings must be supplied by the implementation because this clause leaves them implementation-defined. # p.25
