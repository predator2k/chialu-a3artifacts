## summary
This clause requires arithmetic, conversion, comparison, classification, flag-management, and external-representation operations for supported formats. Numeric computational results are produced as if calculated with infinite precision and unbounded range and then rounded to the destination format. The clause also specifies decimal cohort selection, preferred exponents, special-value behavior, and operation-specific exceptions.

## other_normative
* All conforming implementations shall provide the operations in Clause 5 for every supported arithmetic format, subject to stated exceptions. Computational numeric results use an infinite-precision/unbounded-range intermediate followed by destination rounding.   # p.28
* General-computational operations produce floating-point/integer results, use Clause 4 rounding, and might signal Clause 7 exceptions. Quiet-computational operations produce floating-point results without signaling exceptions. Signaling-computational operations produce no floating-point result and might signal exceptions. Non-computational operations produce no floating-point result and signal no exception.   # p.28
* Homogeneous operations use one format for all floating-point operands/results. `formatOf` operations name the result format independently of operand formats, and each supported arithmetic format has corresponding `formatOf` versions.   # p.28–29
* Operations other than re-encoding operations need not accept or produce differing encodings.   # p.28
* Languages define mappings for `int`, `intFormatOf`, character-sequence types, and `conversionSpecification`. Languages with signed and unsigned integer types should support both kinds for `int` and `intFormatOf`.   # p.29
* Decimal result value/cohort depends on operand values rather than operand representations/encodings. Selection of a representation within the result cohort may depend on operand representations but not their encodings.   # p.29
* For computational operations other than `quantize` and `roundToIntegralExact`, an inexact decimal result uses the cohort member with the least possible exponent. An exact result uses the preferred exponent, or the closest available exponent. `quantize` and `roundToIntegralExact` use the preferred exponent whether exact or inexact.   # p.29
* `Q(x)` is the exponent of the representation of finite `x`; `Q(∞) = +∞`.   # p.29
* Homogeneous general-computational operations shall not propagate non-canonical results.   # p.30–31
* `logBFormat` shall include every integer from `±2 × (emax + p)` inclusive.   # p.31
* When `logBFormat` is integer, the first operand and result of `scaleB` have the same floating-point format. When `logBFormat` is floating point, `scaleB` and `logB` are homogeneous.   # p.31
* `logB(x)` for positive finite `x` is `floor(log2(x))` in a binary format and `floor(log10(x))` in a decimal format.   # p.31
* Arithmetic `formatOf` operations are required for every supported arithmetic destination and operands in every supported arithmetic format with the destination radix. They shall not propagate non-canonical results.   # p.32
* Floating-to-integer operations are required for every supported arithmetic source and every supported signed/unsigned integer destination.   # p.33, p.37
* Conversion operations are required between every pair of supported floating-point formats and between supported formats and decimal character sequences. They shall not propagate non-canonical results.   # p.33
* Conversion operations to/from all supported binary formats and hexadecimal-significand sequences are required by 5.4.3 and never propagate non-canonical floating-point results.   # p.33
* Decimal re-encoding types `decimalEncoding` and `binaryEncoding` are language-defined storage types.   # p.34
* Comparison operands may use different formats if their radices match. Four relations exist: less than/equal/greater than/unordered. Every NaN compares unordered with every value, including itself; zero signs are ignored; same-sign infinities compare equal.   # p.40
* Languages shall deliver comparison results either as one of the four relations or as a Boolean predicate result. Applying logical negation reverses truth values without changing whether unordered input signals invalid.   # p.40
* `totalOrder(−0, +0)` is true and `totalOrder(+0, −0)` is false. Equal negative representations order by decreasing exponent; equal nonnegative representations order by increasing exponent.   # p.39
* In `totalOrder`, negative NaNs order below floating-point numbers and floating-point numbers order below positive NaNs. NaNs order by sign, signaling/quiet kind, and payload; the ordering reverses for negative NaNs where specified.   # p.39
* For canonical operands, both `totalOrder(x, y)` and `totalOrder(y, x)` are true when the operands are bitwise identical. `totalOrder` does not distinguish all non-canonical encodings of one representation.   # p.39
* Conformance/classification predicates should be available at translation time when their values can be determined then. `isCanonical` should be extended appropriately to non-interchange formats.   # p.35–36
* General non-computational operations are required for arithmetic formats and recommended for interchange formats. They are never exceptional, including for signaling NaNs.   # p.36
* A language permitting implicit or mixed-type conversions should require use of the inexact-signaling floating-to-integer conversions.   # p.38
* Binary-to-decimal-to-binary conversion under `roundTiesToEven` shall recover the original floating-point representation, except that a signaling NaN may become quiet. Decimal-to-decimal-character conversion shall be exact and round-trip the representation under the stated rules. Binary-to-hexadecimal-character conversion shall be exact and round-trip the representation under the stated rules.   # p.41
* Translation-time conversion of constants shall use the standard default rounding direction and language-defined exception handling unless the program text specifies otherwise. Character codes are outside the standard.   # p.41
* Character-sequence round trips shall recover zeros/infinities/quiet NaNs and nonzero finite numbers; zero and infinity signs shall be preserved.   # p.42
* Infinity output shall use a language-defined case variant of `inf` or `infinity`, with a minus sign for negative infinity and a language-defined choice of plus sign for positive infinity. Case-insensitive signed `inf`/`infinity` input shall produce infinity with the input sign.   # p.42
* Quiet-NaN output shall use a language-defined case variant of `nan` with an optional sign. Case-insensitive signed `nan` input shall produce a quiet NaN.   # p.42
* Signaling-NaN output should use a language-defined case variant of `snan` or `nan` with an optional sign. Case-insensitive signed `snan` input should produce signaling NaN, or quiet NaN plus invalid operation.   # p.42
* Language standards should provide optional NaN-payload text output. The payload suffix is language-defined, and any provided output form shall also be accepted as input.   # p.42
* Decimal text conversion precision and quantum preservation are mutually incompatible options. Their specification mechanism is language-defined.   # p.42
* Decimal conversions shall preserve value/sign unless rounding is necessary. Input to a decimal format shall preserve quantum unless rounding is necessary, and at least one output conversion for each decimal format shall preserve value/sign/quantum.   # p.42
* An external exponent-width overflow/underflow should be reported with suitable language-defined character sequences.   # p.42
* `Pmin(binary16) = 5`, `Pmin(binary32) = 9`, `Pmin(binary64) = 17`, and `Pmin(binary128) = 36`.   # p.43
* For every other binary format `bf`, `Pmin(bf) = 1 + ceiling(p × log10(2))`; `M = max(Pmin(bf))` over supported binary formats.   # p.43
* `Pmin(decimal32) = 7`, `Pmin(decimal64) = 16`, and `Pmin(decimal 128) = 34`. For every other decimal format `df`, `Pmin(df)` is its number of significant digits.   # p.43
* Conversion to/from supported decimal formats shall be correctly rounded for every requested/given digit count.   # p.43
* A binary-conversion digit limit `H` may be implementation-defined, but `H ≥ M + 3`; `H` should be unbounded. Counts from `1` through `H` shall support correct rounding.   # p.43
* Binary output requesting more than `H` significant digits shall be padded with trailing zeros.   # p.43
* Binary input with more than `H` significant digits or excessive exponent range shall first be correctly rounded to `H` digits under the applicable direction, with exceptions as for narrowing, and then correctly rounded from the resulting `H`-digit sequence.   # p.43
* The stated conversion rules imply correct rounding for decimal conversions and for binary conversions of at most `H` digits; directed constraints/monotonicity and the stated round-trip properties follow.   # p.43
* Language standards should provide conversion between every supported binary format and external hexadecimal-significand character sequences.   # p.44
* A hexadecimal sequence has the grammar `sign [+ −]`, `digit [0123456789]`, `hexDigit [0123456789abcdefABCDEF]`, `hexExpIndicator [Pp]`, `hexIndicator "0" [Xx]`, `hexSignificand ( {hexDigit} * "." {hexDigit}+ | {hexDigit}+ "." | {hexDigit}+ )`, `decExponent {hexExpIndicator} {sign}? {digit}+`, and `hexSequence {sign}? {hexIndicator} {hexSignificand} {decExponent}`.   # p.44
* A `hexSequence` value is the hexadecimal significand multiplied by two raised to the decimal exponent, with negation for a leading minus sign. The indicators do not affect the value.   # p.44
* Hexadecimal output without explicit precision shall contain enough hexadecimal characters to represent the binary value exactly.   # p.44

## model_gaps
* The model has no decimal floating-point format, decimal cohorts, quantum, preferred-exponent selection, or decimal re-encoding, so decimal operation/result requirements cannot be reproduced and can affect representation-exact results.   # p.29–34, p.37, p.42–43
* The model has one NaN without signaling/quiet distinction, payload, sign, or multiple encodings, so signaling behavior, `class`/`isSignaling`, NaN text conversion, and NaN ordering cannot be reproduced. This affects predicate bits, exception observations, and some selected NaN results.   # p.30–31, p.34–36, p.39–42
* The model has no exception flags or traps, so `lowerFlags`, `raiseFlags`, `testFlags`, `testSavedFlags`, `restoreFlags`, `saveAllFlags`, and every required exception observation are unrepresented. This does not change ordinary correctly rounded result bits but does change observable conformance behavior.   # p.28, p.37–44
* The model does not represent canonical versus non-canonical encodings, so canonicalization, propagation permissions, and `isCanonical` cannot be checked. This can affect encoding-exact results without changing numerical values.   # p.30–36, p.39
* The model does not represent external decimal/hexadecimal character sequences or conversion specifications, so text grammar, spelling, precision, `H`, quantum preservation, and round-trip requirements cannot be checked. These requirements affect converted result bits and external representations.   # p.33, p.41–44
* The model’s listed rounding modes omit ties-to-away, which is required for named integer and integral-value conversions. This affects bit-exact results at halfway cases.   # p.38–39
* The model’s stochastic rounding has no semantics in this clause. Applying stochastic rounding to Clause 5 operations would require an extension rather than an IEEE 754-2008 requirement.   # p.28–44
* The model does not describe programming-environment conformance predicates, translation-time availability, or language-defined result types. These gaps affect API/conformance behavior rather than arithmetic result bits.   # p.29, p.35–36, p.41
* The model does not state support for cross-format same-radix operands or independently selected `formatOf` destinations. Missing support would affect bit-exact mixed-format arithmetic/conversion results.   # p.28–33, p.40

## open_questions
* Clause 6 must determine NaN propagation and the remaining behavior for `±0`, `±∞`, and NaN; Clause 7 must determine default exception results/handling. The implementer must not infer those rules from Clause 5.   # p.28, p.30–32
* `minNum`, `maxNum`, and their magnitude variants permit either canonicalized operand in cases not otherwise ordered, so an implementation policy is required where bit-exact reproducibility is expected.   # p.30
* A floating-point `logBFormat` leaves `scaleB(x, N)` behavior language-defined when `N` is non-integral.   # p.31
* An integer `logBFormat` leaves the returned sentinel values for NaN/infinity/zero language-defined within the stated out-of-range constraint.   # p.31
* Floating-to-integer invalid cases depend on whether the implementation can “otherwise” indicate an unrepresentable special value or range error; this indication mechanism and the result value are not specified here.   # p.37
* Languages choose comparison-delivery form, external conversion specifications, decimal encoding storage types, infinity/NaN spellings, NaN payload syntax, exponent-error strings, and the finite binary conversion limit `H`; none of these choices may be guessed by the model.   # p.29, p.34, p.40, p.42–43
