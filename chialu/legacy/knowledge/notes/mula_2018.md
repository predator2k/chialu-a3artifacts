## summary
The document implements population count with AVX2 nibble lookups and an AVX2 Harley-Seal carry-save tree. The AVX2 Harley-Seal implementation reaches 0.52 cycles per 64-bit word and 1.15 cycles per pair for Jaccard computation on sufficiently large arrays. 

## families
### popcount_counter_tree  (role: extends)
mechanism: Harley-Seal maintains ones/twos/fours/eights/sixteens bit-sliced counters and combines groups with 3-input carry-save adders. Each CSA computes the low bit with XOR and the high bit with AND/OR logic. The AVX2 implementation applies this structure to sixteen 256-bit vectors, then invokes the vectorized nibble-lookup population count on the sixteens and remaining counters.   # pp.3-7

## new_families
### simd_nibble_lookup_popcount  (domain: shift: bit counting, closest: popcount_counter_tree, why_not: the method uses SIMD table-shuffle lookup and horizontal accumulation rather than the declared counter-tree primitives)
mechanism: Each byte is split into low/high 4-bit indices. A fixed 16-entry table supplies each nibble’s count through pshufb or vpshufb, byte additions combine the two counts, and psadbw horizontally reduces byte counts. The AVX2 form processes 32 bytes and returns four 64-bit counts; up to sixteen results are accumulated before horizontal reduction.   # pp.5-6
choices: vector_width_bits: {128, 256}; lookup_index_bits: {4}; accumulated_calls_before_horizontal_sum: {8, 16}

## space_gaps
* popcount_counter_tree lacks SIMD vector width/block size choices needed to describe AVX2 Harley-Seal.   # pp.6-7
* popcount_counter_tree.counter_primitive lacks an AVX-512 ternary-logic CSA value, which reduces each CSA from five logical instructions to two.   # p.10
* The bit-counting vocabulary lacks the SIMD nibble-lookup/shuffle mechanism used by Mula’s SSE/AVX2 algorithms.   # pp.5-6

## open_questions
* The document reports 98 µops for AVX2 Harley-Seal but enumerates 16 loads, 32 ANDs, 15 ORs and 30 XORs, which total 93; the remaining µops are not identified.   # p.6
* The document does not identify the physical adder family implementing SIMD additions or final scalar accumulation.
