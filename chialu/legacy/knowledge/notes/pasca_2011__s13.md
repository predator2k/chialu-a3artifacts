## summary
The chapter defines the Table Maker’s Dilemma as finding the hardest-to-round inputs that determine sufficient approximation precision for correct rounding. The chapter proposes an exhaustive, polynomial-based tabulated-differences search mapped to many parallel FPGA cores. The binary64 exponential prototype estimates or achieves hours-to-days execution per input exponent, which is comparable to the L-algorithm and provides an independent check.

## families
### correct_rounding_strategy  (role: analyzes)
mechanism: Correct rounding returns the target rounding function applied to the exact function value. A fixed evaluation precision must distinguish every nonexact midpoint case, so the hardest-to-round inputs determine the required worst-case precision. The proposed search exhaustively evaluates a polynomial approximation modulo one target ulp, filters values whose leading bits approach a midpoint, and sends the candidates for further testing.

## new_families
### table_makers_dilemma_search  (domain: sfu: elementary-function units, closest: correct_rounding_strategy, why_not: correct_rounding_strategy describes the runtime rounding contract, while this mechanism is an offline exhaustive-search accelerator)
mechanism: A Remez polynomial approximates the function on subintervals. Tabulated discrete differences replace successive polynomial evaluations with a pipeline of fixed-point additions modulo 2^(1-p). Each core detects outputs near a rounding midpoint and reports the interval/counter pair. Host-generated initialization vectors periodically restart each core before accumulated initialization error exceeds the bound. Clusters replicate cores, buffer candidate reports, and connect to the host through simple or pipelined credit-based dispatch.

## space_gaps
* The vocabulary lacks an offline hardest-to-round search family with polynomial degree/reinitialization interval/parallel-core count/dispatcher choices.   # p.172-p.183
* correct_rounding_strategy.worst_case_knowledge lacks an independent exhaustive cross-check value for agreement between unrelated algorithms and hardware.   # p.182-p.183

## open_questions
* The chapter leaves the quantitative choice between FPGA initialization hardware and host-software initialization for future study.   # p.174
* The chapter reports performance only for exponential, so performance for other elementary functions remains unknown.   # p.175
* The chapter describes candidate generation and further testing but does not report final hardest-to-round points from the proposed system.   # p.172
* The chapter uses precision p=53 in the binary64 discussion but p=52 in the performance estimate, without reconciling the convention.   # p.172, p.181
