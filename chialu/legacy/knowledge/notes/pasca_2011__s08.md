## summary
The chapter defines an automated fixed-point function evaluator that combines uniform interval splitting, constrained minimax polynomials, Horner evaluation, datapath truncation, and truncated multipliers. The architecture targets faithful rounding, scales to 64 bits or more, and is fully pipelined for FPGA targets. Virtex4/Virtex5 results quantify memory/DSP/latency tradeoffs and compare the polynomial method with CORDIC.   # p.103, p.107, p.110-p.112

### piecewise_poly  (role: proposes)
mechanism: The input interval is split into 2^k uniform subintervals. Each subinterval receives a degree-d polynomial whose constrained coefficients are generated by Sollya fpminimax. One shared evaluator accommodates the worst-case coefficient widths across all subintervals. A recursive error analysis selects internal truncation widths while preserving the requested error bound.   # p.104-p.109

### lut_plus_poly  (role: instantiates)
mechanism: Leading input bits select one row from a coefficient ROM, and the remaining input bits form the local argument y. The selected coefficients feed one shared local polynomial evaluator, followed by final rounding.   # p.104, p.108-p.109

### horner  (role: instantiates)
mechanism: The evaluator computes p(y)=a0+y×(a1+y×(a2+...+y×ad)...). Each step truncates the product πj and may truncate y before multiplication. The recurrence propagates bounds on both truncation terms through subsequent steps.   # p.106-p.108
choices:
  none
new_choices:
  product_guard_bits: gjπ — retains bits beyond the corresponding coefficient LSB   # p.107
  argument_guard_bits: gjy — controls the truncated y input to each multiplication   # p.107
slots:
  none
parameters: 0≤gjπ<5 in the reported experiments; d is user-specified.   # p.104, p.107
results:
| metric | value | unit | technology / device | baseline | condition | page |
| operation count | minimum among discussed schemes | abstract operations | abstract | developed-form parallel evaluation | Horner evaluation | p.106 |
errors_and_checks: A recursive C++ analysis accepts parameters only when εeval<u/2−εapprox.   # p.108-p.109
conditions: Horner minimizes operations at the expense of latency. Later-step truncations can save more DSP blocks because multiplication sizes increase with j.   # p.106, p.109
evidence: Sections 7.2.3-7.2.5; Figures 7.4-7.5; Table 7.1.

## taxonomy
* Function-evaluation methods
  * Function-specific methods
    * CORDIC variants -> cordic   # p.101
  * Generic polynomial methods
    * Range reduction
      * Uniform 2^k interval splitting by leading input bits -> uniform_high_bit_decode   # p.104
      * Function-specific/logarithmic segmentation -> unmapped   # p.104
    * Polynomial approximation
      * Taylor approximation -> piecewise_poly   # p.104
      * Chebyshev approximation -> piecewise_poly   # p.104
      * Real-coefficient Remez minimax followed by coefficient rounding -> piecewise_poly   # p.105
      * Rounded minimax plus neighboring-polynomial search -> piecewise_poly   # p.105
      * Constrained modified Remez/fpminimax -> piecewise_poly   # p.105
    * Polynomial evaluation
      * Developed-form parallel monomials/HOTBM -> parallel_monomial   # p.102, p.106
      * Sequential Horner evaluation -> horner   # p.106
      * Odd/even decomposition and Estrin variants -> estrin   # p.106
      * Algebraic refactoring -> factored   # p.106
    * Multiplier implementation
      * Full-width standard datapath -> unmapped   # p.110
      * Per-step input-width trimming -> unmapped   # p.107-p.110
      * Product-bit truncation -> truncated_fixed_width   # p.109-p.110

## space_gaps
* `piecewise_poly.segments` stops at 64, while the chapter reports 128 through 8192 subintervals.   # p.111
* `lut_plus_poly.index_bits` stops at 12, while the chapter reports 8192=2^13 subintervals.   # p.111
* `range_reduction.method` lacks the chapter’s zero-cost uniform leading-bit interval split.   # p.104
* `piecewise_poly.coefficient_optimization` lacks constrained fpminimax followed by neighboring bit-width/memory-sweet-spot exploration.   # p.105-p.106
* The vocabulary lacks FPGA BRAM packing and DSP-input sweet-spot choices that drive the reported implementation search.   # p.106, p.108-p.109
