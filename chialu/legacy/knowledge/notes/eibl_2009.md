## summary
The document proposes a reduced-precision floating-point adder that checks a full-precision fp32 adder while retaining the sign/exponent and truncating the checker mantissa (pp.145-146). The checker provides a tunable bound on undetected-error magnitude at area overheads from 30% to 62% for the evaluated widths (pp.149-151).

## families
### reduced_precision  (role: proposes)
mechanism: A fully featured reduced-precision floating-point adder operates in parallel with the primary adder using the operands' most-significant bits. The checker retains the full sign and exponent but truncates the mantissa. An adjustment unit maps the two-bit difference between the full result and checker result to chk, chk+1, chk+2, or chk-1 before comparison. The checker rounder is omitted because the comparison tolerates these small differences. check_valid suppresses checking for unlike-sign operands with close exponents. (pp.146-149)

errors_and_checks: For an m-bit checker mantissa, the analytical maximum undetected error is less than 4×2^-m = 2^-m+2 (p.149). Fault injection models activated single stuck-at faults throughout the primary adder/checker adder/adjustment-comparison hardware using wire-value inversion, with 50,000 input patterns per fault and approximately one billion experiments overall (p.150). Faults in checker/comparison hardware can produce false positives; primary-adder errors below the checker resolution can produce false negatives (pp.146, 150). The measured maximum errors remain within the analytical bounds (p.151).
conditions: The method checks the same sign/exponent and only the most-significant mantissa bits, so increasing checker width reduces undetected-error magnitude while increasing area and false positives from the larger checker (pp.146, 150-151). The method suppresses checking for unlike-sign operands with exponent differences of zero or one because cancellation makes the truncated computation a poor predictor (pp.147-149). Detection may fit in the addition cycle when the output path has slack; otherwise lazy error detection requires that the result remain uncommitted until the following cycle (pp.148-149). The acceptable error bound depends on the application, and chains of operations can accumulate more error than one addition (p.149).
evidence: §3 and Figures 1-2 define the checker/adjustment structure (pp.146-148); §4.1-4.2 describes area/timing (pp.148-149); §4.3 and Figures 3-4 define the fault model and error analysis (pp.149-151); Table 2 reports the quantitative tradeoff (p.151).

## space_gaps
* reduced_precision.replica_width_bits does not distinguish total checker width from retained mantissa width, which is the paper's primary tuning parameter (pp.146, 151).
* reduced_precision lacks choices for tolerated-result adjustment and suppression of cancellation cases, which determine the error bound and coverage (pp.147-149).
* reduced_precision lacks checker-rounding removal, which reduces redundant-adder area in this design (p.148).

## open_questions
* Section 3.2 suppresses checks for unlike-sign operands whose exponent difference is zero or one, while §4.3.1 and the conclusion describe the excluded case more narrowly as matching/equal exponents (pp.148-149, 151-152).
* The synthesis technology and standard-cell library are not reported, so the Table 2 area overheads cannot be tied to a technology node (pp.148, 151).
