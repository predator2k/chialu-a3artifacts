## summary
This clause fixes infinity arithmetic, NaN behavior/encoding/propagation, and result-sign rules. It distinguishes signaling and quiet NaNs and specifies binary/decimal NaN payload handling.

## other_normative
* All floating-point operations shall support signaling and quiet NaNs. # p.45
* Quiet NaNs should provide retrospective diagnostic information by an implementation-defined means. # p.45
* NaN results should preserve as much diagnostic information as possible. # p.45
* Every encoded NaN has a sign bit, a NaN/kind-identifying pattern, and remaining trailing-significand bits that encode the payload. # p.45
* Every binary NaN has every biased-exponent-field bit `E` set to `1`. # p.46
* A binary quiet NaN should have the first trailing-significand bit `d1` set to `1`. # p.46
* A binary signaling NaN should have the first trailing-significand bit set to `0`. # p.46
* When the first trailing-significand bit is `0`, another trailing-significand bit must be non-zero to distinguish NaN from infinity. # p.46
* A binary NaN payload occupies the `p − 2` least significant bits of the trailing significand field. # p.46
* A decimal NaN payload is the trailing significand field defined in 3.5. # p.46
* Means should exist to read/write NaN payloads from/to external character sequences. # p.46
* The standard does not interpret a NaN’s sign. # p.46
* `copy`, `negate`, `abs`, and `copySign` specify the sign bit of a NaN result, and `totalOrder` is affected by a NaN operand’s sign bit. # p.46
* For operations other than `copy`, `negate`, `abs`, `copySign`, and `totalOrder`, the standard does not specify the sign bit of a NaN result. # p.46

## model_gaps
* The model has one NaN and lacks the required signaling/quiet distinction, which affects invalid-operation behavior and the bit-exact quieting result. # p.45
* The model has no exception flags or traps, so it cannot represent required invalid-operation signaling or the infinity-related exception signals; this omission does not always affect result bits, but invalid operations also require a quiet NaN result. # p.45
* The model lacks NaN payloads, so it cannot reproduce payload preservation/selection/canonicalization or binary `d1` quieting bit patterns. # p.46
* The model lacks decimal floating-point formats, so it cannot reproduce `G5`, `G6` through `Gw + 4`, decimal trailing-significand canonicalization, or decimal payload rules. # p.46
* A single undifferentiated NaN cannot reproduce NaN sign-bit behavior for `copy`/`negate`/`abs`/`copySign`/`totalOrder` if the model does not retain a NaN sign, which affects bit-exact results and ordering. # p.46
* The model does not represent external character-sequence access to NaN payloads, which does not affect arithmetic result bits but does affect conversion behavior. # p.46

## open_questions
* Clause 6 does not specify which input NaN supplies the result payload when multiple NaNs are present. # p.46
* Clause 6 does not specify the NaN result sign for operations other than `copy`, `negate`, `abs`, `copySign`, and `totalOrder`. # p.46
* The condition under which `fusedMultiplyAdd` with only quiet NaN inputs might signal invalid operation requires 7.2. # p.45
* The behavior of maximum/minimum with quiet NaN inputs is excluded from the general quiet-NaN result rule and must be obtained from their operation definitions. # p.45
