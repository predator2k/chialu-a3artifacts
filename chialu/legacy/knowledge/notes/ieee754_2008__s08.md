## summary
This clause defines recommended resuming/immediate/delayed alternate handling for invalid operation, divideByZero, overflow, underflow, inexact, and language-defined sub-exceptions. It requires specific abrupt-underflow results and distinguishes when immediate and delayed underflow handlers are invoked.

## other_normative
* Language standards should define means for users to associate alternate exception handling attributes with blocks, and implementations should be required to provide those means. # p.50
* Alternate exception handlers specify exception lists and actions taken when each listed exception is signaled. # p.50
* Language standards should define exception lists containing any subset of invalid operation/divideByZero/overflow/underflow/inexact. # p.50
* Language standards should define `allExceptions` as all five Clause 7 exceptions and should define lists containing any subset of language-named sub-exceptions. # p.50
* Language standards should define all alternate exception handling attributes in this clause, including at least one delayed attribute for each Clause 7 exception. # p.50
* The syntax and scope of alternate attribute values are language-defined. # p.50
* A resuming alternate exception handling attribute handles the implied exceptions according to the specified attribute and resumes execution of the associated block. # p.50
* Implementations should support `default (raise flag)`/`raiseNoFlag`/`mayRaiseFlag`/`recordException`/`substitute(x)`/`substituteXor(x)`/`abruptUnderflow`. # p.50
* A recorded exception description includes language-standard-defined details that might include the current operation/operands and exception location. Language standards define operations to convert descriptions to/from character sequences and to inspect/save/restore descriptions. # p.50
* `abruptUnderflow` has no effect on the interpretation of subnormal operands. # p.51
* Language standards should define immediate handler blocks/delayed handler blocks/immediate transfers/delayed transfers and require implementations to provide them. # p.51
* An immediate handler abandons the associated block as soon as possible, executes the handler, and continues where normal block termination would have continued according to the language semantics. # p.51
* A delayed handler applies default handling until normal block termination, executes the handler, and then continues where normal block termination would have continued according to the language semantics. # p.51
* An immediate transfer transfers control as soon as possible and permits no return. # p.51
* A delayed transfer applies default handling until normal block termination, then transfers control and permits no return. # p.51
* Delayed handling is fully deterministic; immediate handling permits, but does not require, nondeterministic intermediate results in exchange for performance. # p.51
* For a flag-based implementation of delayed handling, the corresponding status flag should be saved and lowered before the block; the current flag should be saved and the original restored after the block; the recently saved flag should then determine whether the handler runs or control transfers. # p.51
* Immediate handling can be implemented by traps or, except for underflow, by testing status flags after each operation or at block termination. # p.51
* If the indicated exception is not signaled, the corresponding status flag should remain unchanged. If the exception causes a handler or transfer, the flag state might be nondeterministic. # p.51
* A transfer is informatively described as a language-specific non-resumable control transfer, with `break`/`throw exceptionName`/`goto label` given as examples. # p.51

## model_gaps
* The model has no status flags, so `default (raise flag)`/`raiseNoFlag`/`mayRaiseFlag`/`recordException` and flag preservation cannot be represented; this does not affect ordinary default result bits but does affect observable exception state. # p.50-p.51
* The model has no traps, handlers, block control flow, or exception records, so immediate/delayed handlers/transfers and `recordException` cannot be represented; these attributes can change whether operations execute and therefore can affect externally observed results. # p.50-p.51
* The model has one NaN and cannot preserve distinctions that a language-defined expression `x` or recorded operand description might contain; `substitute(x)` and `substituteXor(x)` can affect bit-exact results. # p.50
* The model’s optional output flush-to-zero does not represent `abruptUnderflow`, which can select signed zero or a signed minimum-normal result according to rounding direction and must signal inexact; this affects bit-exact results. # p.50-p.51
* The model does not represent `roundTiesToAway`, so the required `abruptUnderflow` result for that rounding attribute is unavailable; the required result magnitude is zero. # p.50
