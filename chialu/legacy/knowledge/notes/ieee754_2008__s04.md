## summary
This clause defines attribute specification, dynamic modes, and rounding-direction attributes. It requires infinitely precise intermediate results with unbounded range before rounding unless otherwise stated. It defines two nearest-rounding attributes, three directed-rounding attributes, and their availability/default requirements.

## formats

## rounding
| mode | definition (quoted) | tie rule | level | page |
|---|---|---|---|---|
| roundTiesToEven | “the floating-point number nearest to the infinitely precise result shall be delivered” | “if the two nearest floating-point numbers bracketing an unrepresentable infinitely precise result are equally near, the one with an even least significant digit shall be delivered” | required | p.27 |
| roundTiesToAway | “the floating-point number nearest to the infinitely precise result shall be delivered” | “if the two nearest floating-point numbers bracketing an unrepresentable infinitely precise result are equally near, the one with larger magnitude shall be delivered” | required for decimal; not required for binary | p.27 |
| roundTowardPositive | “the result shall be the format’s floating-point number (possibly +∞) closest to and no less than the infinitely precise result” | n/a | required | p.27 |
| roundTowardNegative | “the result shall be the format’s floating-point number (possibly −∞) closest to and no greater than the infinitely precise result” | n/a | required | p.27 |
| roundTowardZero | “the result shall be the format’s floating-point number closest to and no greater in magnitude than the infinitely precise result” | n/a | required | p.27 |

## other_normative
* Language standards shall specify rounding-direction attributes. # p.26
* Language standards should specify alternate exception-handling attributes. # p.26
* Language standards that permit more than one mapping of language expressions into standard operations should support preferredWidth attributes, value-changing optimization attributes, and reproducibility attributes. # p.26
* The implementation shall provide language-defined means, such as compiler directives, to specify a constant attribute-parameter value for all standard operations in a block; the associated block is the scope of that value. # p.26
* Language standards shall permit constant specification of the default and each specific attribute value. # p.26
* Attributes shall support the constant specification defined in 4.1. # p.26
* Language standards should support dynamic-mode specification of attributes, particularly for debugging. # p.26
* For dynamic-mode specification, the implementation shall provide language-defined means for an attribute parameter to assume the value of a dynamic-mode variable for all standard operations within the specification’s block scope. # p.26
* The implementation initializes a dynamic-mode variable to the default value for the dynamic mode. # p.26
* Changes to a dynamic-mode variable within its language-defined dynamic scope are controlled by the user through the referenced operations. # p.26
* The precedence of static attribute specifications and dynamic-mode assignments is language-defined and may be deferred to implementations. # p.26
* The effect of changing a dynamic-mode variable during an asynchronous event is language-defined and may be deferred to implementations. # p.26
* Whether a dynamic-mode variable can be determined by non-programmatic means is language-defined and may be deferred to implementations. # p.26
* The rounding-direction attribute affects all computational operations that might be inexact, the signs of exact zero sums, and the thresholds beyond which overflow and underflow are signaled. # p.27
* Implementations supporting both decimal and binary formats shall provide separate binary and decimal rounding-direction attributes. # p.27
* For roundTiesToEven and roundTiesToAway, an infinitely precise result with magnitude at least b emax (b − ½ b 1−p) shall round to ∞ without a sign change; emax and p are determined by the destination format. # p.27
* An implementation shall provide roundTiesToEven, roundTowardPositive, roundTowardNegative, and roundTowardZero. # p.27
* A decimal-format implementation shall provide roundTiesToAway as a user-selectable rounding-direction attribute. # p.27
* A binary-format implementation is not required to provide roundTiesToAway. # p.27
* roundTiesToEven shall be the default rounding-direction attribute for binary-format results. # p.27
* The default rounding-direction attribute for decimal-format results is language-defined but should be roundTiesToEven. # p.27

## model_gaps
* The model has no decimal floating-point format, decimal rounding-direction attribute, or roundTiesToAway mode. This gap affects bit-exact decimal results but does not affect the represented binary formats because roundTiesToAway is not required for binary implementations. # p.27
* The model has no program-block attribute scope, constant attribute specification, or dynamic-mode variable. This gap can affect bit-exact results when different operations execute under different rounding-direction attribute values. # p.26
* The model has no exception flags or traps. This gap does not change result bits, but it prevents verification of the required signaling behavior and rounding-dependent overflow/underflow thresholds. # p.27
* The model does not state support for rounding-dependent signs of exact zero sums. This gap affects bit-exact zero encodings if that behavior is absent. # p.27

## open_questions
* The reference “operations in 9.3.1 and .” is incomplete in the supplied clause text, so the second referenced set of operations cannot be identified. # p.26
* The language standard must define the default decimal rounding-direction attribute; this clause recommends roundTiesToEven but does not require it. # p.27
