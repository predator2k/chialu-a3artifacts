## summary
This clause defines reproducible operations/attributes/status flags/formats and the language/user conditions that produce the same numerical and reproducible status-flag results across platforms. The clause requires conforming language standards that support reproducible programming to provide an unambiguous reproducible-results mode.

## other_normative
* **Required definition:** “A reproducible operation is one of the operations described in Clause 5 or is a supported operation from 9.2 or 9.3.” # p.62
* **Required definition:** “A reproducible attribute is an attribute that is required by a language standard in all implementations (see 4).” # p.62
* **Required definition:** “A reproducible status flag is one raised by the invalid operation, division by zero, or overflow exceptions (see 7.2, 7.3, and 7.4).” # p.62
* **Required definition:** “A reproducible format is an arithmetic format that is also an interchange format (see 3).” # p.62
* **Informative:** Programs reliably translated into an explicit or implicit sequence of reproducible operations on reproducible formats produce the same numerical and reproducible status-flag results. # p.62
* **Recommended:** “A language standard should support reproducible programming.” # p.62
* **Required:** A conforming language standard supporting reproducible programming shall support the reproducible-results attribute. # p.62
* **Required:** A conforming language standard supporting reproducible programming shall support a reproducible format by providing all reproducible operations for that format. # p.62
* **Required:** A conforming language standard supporting reproducible programming shall provide means to specify explicitly or implicitly any sequence of reproducible operations on supported reproducible formats. # p.62
* **Required:** The language standard shall define which language element corresponds to each supported reproducible format. # p.62
* **Required:** The language standard shall define how each reproducible operation is specified for each supported reproducible format. # p.62
* **Required:** The language standard shall provide one or more unambiguous expression-evaluation rules for user selection on all conforming implementations, without deferring any aspect to implementations. # p.62
* **Required:** If the language standard permits more than one interpretation of a sequence of operations from this standard, it shall provide a means, such as prescriptive parentheses, to specify an unambiguous evaluation. # p.62
* **Required:** The language standard shall define a reproducible-results attribute, as described in 4.1, whose values indicate whether reproducible results are required. The language standard defines the default value. # p.62
* **Required:** When reproducible results are selected, execution behavior shall preserve the literal meaning of the source code as specified in 10.4. # p.62
* **Required:** When reproducible results are selected, conversions to and from external decimal character sequences shall not limit the maximum supported precision H specified in 5.12.2. # p.62
* **Required:** When reproducible results are selected, language processors shall indicate where reproducibility cannot be guaranteed for operations that can affect floating-point results. # p.62
* **Required:** When reproducible results are selected, only default exception handling specified in Clause 7 shall be used. # p.62
* **Required:** A language with separately compiled routines must provide a mechanism that ensures reproducible behavior. # p.62
* **Required condition for reproducibility:** Programs use the reproducible-results-required attribute. # p.62
* **Required condition for reproducibility:** Programs use only reproducible floating-point formats. # p.62
* **Required condition for reproducibility:** Programs use only reproducible floating-point operations, explicitly or implicitly through expressions. # p.62
* **Required condition for reproducibility:** Programs use only rounding/preferredWidth attributes required in every implementation. # p.62
* **Required condition for reproducibility:** Programs use only integer/non-floating-point formats supported in every implementation of the language standard and avoid signaling integer-arithmetic or other implementation-defined exceptions. # p.63
* **Required condition for reproducibility:** Programs do not use value-changing optimizations specified in 10.4. # p.63
* **Required condition for reproducibility:** Programs do not exceed system limits. # p.63
* **Required condition for reproducibility:** Programs do not use fusedMultiplyAdd(0, ∞, c) or fusedMultiplyAdd(∞, 0, c) when c is a quiet NaN. # p.63
* **Required condition for reproducibility:** Programs do not use signaling NaNs. # p.63
* **Required condition for reproducibility:** Programs do not depend on the sign of a zero result or the quantum of a decimal result for minNum(x, y), maxNum(x, y), minNumMag(x, y), or maxNumMag(x, y) when x and y are equal. # p.63
* **Required condition for reproducibility:** Programs do not depend on quiet-NaN propagation/payloads/sign bits. # p.63
* **Required condition for reproducibility:** Programs do not depend on underflow/inexact exceptions or flags. # p.63
* **Required condition for reproducibility:** Programs do not depend on the quantum of results from operations on decimal formats in Table 9.1. # p.63
* **Required condition for reproducibility:** Programs do not depend on encodings, including type overlays. # p.63

## model_gaps
* The model has no status flags, so it cannot reproduce or check the invalid-operation/division-by-zero/overflow status-flag results covered by this clause. This gap does not affect bit-exact numerical results. # p.62
* The model has no reproducible-results attribute, language-expression rules, source-level literal meaning, compiler optimizations, or system limits. These gaps can affect whether a source program maps to the required bit-exact operation sequence, but they do not affect evaluation of an already fixed sequence. # p.62-63
* The model has one NaN without signaling/quiet distinctions, payloads, or sign bits. The clause excludes programs that use signaling NaNs or depend on quiet-NaN propagation/payloads/sign bits, so the gap does not affect results within the reproducibility conditions. # p.63
* The model does not represent decimal formats/quantum or external decimal character conversion precision H. These gaps affect bit-exact decimal results and conversion coverage. # p.62-63
* The model does not represent preferredWidth. This gap can affect the selected intermediate/result format and therefore bit-exact results when preferredWidth influences evaluation. # p.62

## open_questions
* The clause leaves each language standard to identify its supported reproducible formats/operations, required attributes, default reproducible-results value, and unambiguous evaluation rules; an implementer must obtain those choices from the applicable language standard. # p.62
