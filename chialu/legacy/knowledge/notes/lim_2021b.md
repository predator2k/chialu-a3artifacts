## summary
RLibm-32 generates correctly rounded elementary-function libraries for fp32 and posit32 by synthesizing polynomials against rounding intervals rather than real-valued minimax error (§3). Counterexample-guided LP synthesis, bit-pattern domain splitting, and range-reduction analysis make exhaustive 32-bit correctness feasible (§3.2-§3.4). The prototype implements ten fp32 functions and eight posit32 functions (§4.1).

## families
### correct_rounding_strategy  (role: extends)
mechanism: RLibm-32 computes each input's oracle result and its interval in higher-precision H that rounds to that result in target representation T. Range reduction maps these constraints to reduced intervals. An exact rational LP solver synthesizes polynomial coefficients from a sample; exhaustive checking adds every violating reduced input as a counterexample until all inputs satisfy their intervals. Multiple functions used by output compensation receive jointly widened reduced intervals (§3.1-§3.4).
choices:
  strategy: rlibm_interval_synthesis   # §3
  worst_case_knowledge: published_exhaustive   # §4.2
  rounding_modes_covered: nearest_only   # §3.1
new_choices:
  polynomial_generation: counterexample_guided_linear_programming — samples reduced constraints and iteratively adds violating inputs   # §3.4
  multi_function_interval_deduction: simultaneous_bound_expansion — widens every component function's reduced interval while output compensation remains inside the target rounding interval   # §3.2
slots: none
parameters: T is fp32 or posit32; H is double; MPFR uses up to 400 precision bits; SoPlex has a five minute limit; the counterexample sample threshold is 50,000 constraints   # §4.1

### piecewise_poly  (role: extends)
mechanism: Reduced inputs are divided first by sign and then into 2^n sub-domains using the next n bits after the common most-significant prefix of the smallest and largest reduced inputs. Each sub-domain receives an LP-synthesized polynomial whose evaluated value must remain within every reduced rounding interval. Coefficients are stored in a bit-pattern-indexed table and evaluated with Horner's method in double (§3.3-§4.1).

  coeff_encoding: plain   # §3.4
  coefficient_optimization: rounding_interval_linear_programming [outside domain]   # §3.4
  rounding_contract: exact   # §4.2
new_choices:
  subdomain_addressing: common_prefix_following_bits — indexes sub-domains with bits following the common prefix of reduced inputs   # §3.3
  constraint_sampling: counterexample_guided — adds interval violations until exhaustive checking succeeds   # §3.4
slots:
  range_reducer: range_reduction [method=table_augmented]   # Appendix A

  segmenter: uniform_high_bit_decode   # §3.3
parameters: maximum requested degree 8; maximum 2^14 sub-domains; generated fp32 degrees 3-5; generated posit32 degrees 3-6; ten fp32 and eight posit32 functions   # Table 3, §4.2

### range_reduction  (role: extends)
mechanism: Table-augmented reductions map logarithmic, exponential, trigonometric, and hyperbolic functions to small domains evaluated in double. Output compensation reconstructs the target function from polynomial results and tables. For compensation involving multiple elementary functions, RLibm-32 derives component intervals simultaneously. The cospi reduction changes an a+b identity to an a-b formulation so compensation is monotonic and avoids cancellation (§5; Appendix A).
choices:
  method: table_augmented   # Appendix A
  reduction_type: additive   # Appendix A.1, A.3-A.6
  worst_case_bound_proven: false   # §7
new_choices:
  output_compensation_arity: multiple_functions — one result can depend on jointly constrained sinpi/cospi or sinh/cosh approximations   # §3.2
  compensation_monotonicity: required — interval deduction handles increasing or decreasing compensation   # §3.2
slots: none
parameters: sinpi uses 512 table values and R in [0, 1/512]; cospi uses 514 table values and R in [0, 1/512]; logarithms use 128-entry tables; exponential reductions use 64 or 128 segments   # §2.1, §5, Appendix A
results:
| metric | value | unit | technology / device | baseline | condition | page |
| sinpi reduced inputs | 117 million | inputs | software / Intel Xeon Gold 6230R | unreduced fp32 domain | R in [0, 1/512] | Appendix B.7 |
| cospi reduced inputs | 40 million | inputs | software / Intel Xeon Gold 6230R | unreduced fp32 domain | monotonic compensation, R in [0, 1/512] | Appendix B.8 |
errors_and_checks: Numerical errors from range reduction/polynomial evaluation/output compensation are included in reduced rounding intervals; exhaustive final validation supplies the correctness check   # §3.1-§3.4
conditions: Nonmonotonic compensation is unsupported by ReducedIntervals (§3.2). Some trigonometric functions may require higher-precision reduction, and exhaustive double-precision validation remains unresolved (§7).
evidence: §2.1-§2.2; §3.2; §5; Appendices A-C

## space_gaps
* correct_rounding_strategy lacks choices for counterexample-guided LP sampling and simultaneous reduced-interval deduction for multi-function compensation (§3.2-§3.4).
* piecewise_poly lacks the common-prefix-following-bit segmentation value and rounding-interval LP coefficient synthesis (§3.3-§3.4).
* range_reduction lacks output-compensation arity/monotonicity choices (§3.2).

## open_questions
* The document does not state support for IEEE rounding modes other than the RN operation used throughout.
* The document does not provide a proof method for validating all double inputs, which it identifies as an open problem (§7).
