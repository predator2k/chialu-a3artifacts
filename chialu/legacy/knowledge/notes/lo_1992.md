## summary
The document develops Berger check prediction equations for arithmetic/logic/shift/rotate operations and implements an SFS Berger check prediction ALU. The BCP ALU uses ALU internal carries and permits an entirely Berger-encoded processor datapath with one TSC Berger checker. The BCP 8080 requires 3330 gates and 92% additional hardware, compared with 3678 gates and 113% additional hardware for the cited two-rail SFS 8080. # p.538-539

## families
### self_checking_datapath  (role: extends)
mechanism: Separate arithmetic and logic units feed a result multiplexer. The BCP circuit selects the ALU internal-carry vector or a logic-derived vector, counts its zeros, and combines that count with the operands’ Berger symbols through a multiple-input signed adder to predict the result symbol. The information result and predicted symbol form a Berger codeword. Ripple-carry, Manchester-chain, and modified group-lookahead arithmetic units are analyzed under gate/transistor faults. # p.528-535

errors_and_checks: The ALU part is proved fault-secure/self-testing for single stuck-at, stuck-open, and stuck-on faults under the stated circuit conditions. Any erroneous BCP-symbol output paired with a correct ALU result is a noncodeword. The complete unit is SFS for ALU faults plus arbitrary deterministic BCP-circuit fault sets, and it is single-error detection lossless for a noncodeword operand. # p.529-536
conditions: Arithmetic and logic units must be separated to prevent multiple random logic errors. Group-lookahead implementations require independent propagate/half-sum circuits and separately computed group output carries; the stated overhead is one XOR per bit plus three two-input AND gates and one three-input OR gate per group. CMOS circuits with nondeterministic stuck-on behavior require n-dominant or p-dominant gates. Carry-chain reuse for left shift/rotate requires the modified prediction equations and input multiplexing. BCP delay is O(log2 n), but pipeline overlap can make its added processor critical-path delay negligible. # p.529-537
evidence: §II equations (3), (5), and (9)-(24); Fig. 1/Table II; Fig. 3-6; Theorems 4-11; Tables III-VI. # p.526-539

### berger  (role: extends)
mechanism: The information word is encoded with the binary representation of its number of zeros. The result symbol is predicted from operand symbols and operation-dependent quantities rather than regenerated solely from the result. Arithmetic prediction uses the ALU carry vector; logic prediction uses counts of AND/OR-derived vectors; rotate preserves the symbol, while shifts adjust it for inserted and discarded bits. # p.526-528
choices:
  check_field: full_log   # p.526
  granularity: endpoint   # p.538
new_choices:
  check_generation: operation_prediction — computes the result Berger symbol concurrently from operands/check symbols/internal operation signals   # p.525-528
slots:
  none
parameters: check symbol encodes the number of zeros; arithmetic relation S_c = X_c + Y_c - C_c - c_in + c_out; processor example uses one TSC Berger checker in the datapath   # p.526, p.538

errors_and_checks: Berger coding guarantees detection of all unidirectional information/check-symbol errors. The BCP construction forces the analyzed ALU faults to produce a noncodeword rather than relying on every raw ALU error being unidirectional. # p.529-536

## space_gaps
* `self_checking_datapath.encoding` lacks `berger_check_prediction`, although the document establishes a self-checking datapath that emits Berger codewords. # p.525, p.528
* `self_checking_datapath` lacks a base-ALU slot for `ripple_carry`, `manchester_carry_chain`, and `carry_lookahead`, whose fault behavior and required modifications differ. # p.529-534
* `berger` lacks a choice distinguishing result checking from operation-dependent check prediction. # p.526-528

## open_questions
* The cited implementations of the TSC Berger checker and 1’s counter are not reproduced, so the `comparator` slot cannot be assigned to `two_rail_tree`. # p.528, p.537
* The technology/device for the transistor, delay, and gate estimates is not reported. # p.537-539
* Table VI labels the 16/32/64-bit processors hypothetical and does not state all scaling assumptions used to obtain their overhead percentages. # p.539
