## summary
The paper proposes a residue checker for binary multiply-accumulate circuits using radix-two signed-digit modulo \(2^p\pm1\) arithmetic and a merged/balanced adder tree (pp.1, 4-5). The signed-digit implementations reduce checker delay relative to ordinary binary residue arithmetic in a 0.18μm CMOS gate-array synthesis (p.6).

## families
### residue  (role: extends)
mechanism: The checker computes \(z=\langle\langle A\rangle_m\times\langle B\rangle_m+\langle C\rangle_m\rangle_m\), independently converts \(Z\) to \(z'=\langle Z\rangle_m\), and signals an error when \(E=z-z'\neq0\). Modulo \(m=2^p+u\), \(u\in\{-1,1\}\), arithmetic uses radix-two signed digits. Binary-to-residue conversion, partial-product reduction, addition and subtraction are merged into a balanced binary tree of modulo signed-digit adders. Switching \(u\) changes the modulus and detects some two-bit errors that alias under the other modulus (pp.2, 4-5).
choices:
  modulus: \(2^p-1\) / \(2^p+1\) [outside domain]   # pp.1-2
  granularity: endpoint   # pp.2, 4
  comparison_point: writeback   # pp.2, 4
  generator_style: signed_digit_adder_tree [outside domain]   # pp.4-5
  ops_per_checker: 1   # p.2
new_choices:
  tree_organization: merged_balanced_binary — converter/multiplier/addition trees are merged and balanced to shorten the longest path   # pp.4-5
slots:
  none
parameters: \(A,B\): n bits; \(C,Z\): 2n bits (p.1); \(p\)-digit residue, physically encoded in 2p bits (p.5); synthesized n={32,64}, p={4,8,9,10,11,12,16} (p.6); optimal latency \(\log_2(n/p)+\log_2p+1\) signed-digit-adder stages (p.6); for n=32, the p=8/p=9/p=4 balanced trees each have 6 stages and respectively 232/about 270/176 add1 and add2 cells (p.5).

errors_and_checks: Any fault in the product-sum circuit or checker is detected when \(E\neq0\); errors whose corrupted result has the same residue alias (pp.2, 4). A two-bit error example aliases for m=7 but is detected after switching to \(u=1\) (pp.2, 4). Detection coverage/false-alarm rate are not quantified.
conditions: Modulo signed-digit addition time is independent of operand wordlength because carry propagation is avoided beyond one position (pp.1, 3). Multiplication and binary-to-residue conversion take time proportional to \(\log_2p\) and \(\log_2(n/p)\), respectively (p.4). The paper prefers p=8 when multiple moduli are used because it balances delay/circuit cost and detects more two-bit errors than p=4 (pp.5-6). Simultaneous checking with \(u=-1\) and \(u=1\) requires two residue checkers (p.6).
evidence: §II equations (1)-(6) and Fig.1 (pp.1-2); §III-B-D, Figs.2-5 (pp.3-4); §III-E, Figs.6-7 (p.5); Tables III-IV (p.6).

### generalized_signed_digit  (role: extends)
mechanism: A p-digit radix-two number uses digits \(x_i\in\{-1,0,1\}\). The modulo adder first produces \(c_i\in\{-1,0\}\) and \(s_i\in\{0,1\}\), then forms \(z_i=s_i+c_{i-1}\) with end-around carry \(c_{-1}=u c_{p-1}\). Each intermediate carry/sum therefore needs one binary bit. The paper encodes an external signed digit with sign and absolute-value bits (pp.2-3, 5).
choices:
  radix: 2   # p.2
  digit_encoding: sign_magnitude   # p.5
  addition_scheme: two_stage_limited_carry   # pp.1, 3
new_choices:
  intermediate_encoding: one_bit_sum_and_carry — \(s_i\) and \(c_i\) each have only two values and use one binary digit internally   # p.3
slots:
  none
parameters: digits \(x_i\in\{-1,0,1\}\); p add1 cells and p add2 cells per modulo signed-digit adder; moduli \(2^p+u\), \(u\in\{-1,1\}\)   # pp.2-3

## space_gaps
* `residue.modulus` lacks parametric \(2^p-1\) and \(2^p+1\) values, including the plus-one modulus used by the checker (pp.1-6).
* `residue.generator_style` lacks a radix-two signed-digit adder tree (pp.3-5).
* `residue` lacks a choice for merged/balanced checker-tree organization (pp.4-5).

## open_questions
* Tables III-IV do not state whether their synthesized results use \(u=-1\), \(u=1\), or a shared implementation evaluated in one mode.
* The abstract gives \(\log_2n+\log_2(n/p)+1\) stages, while the conclusion gives \(\log_2(n/p)+\log_2p+1\); the six-stage n=32 examples agree with the conclusion (pp.1, 5-6).
* The abstract calls p=8 best in delay, but Table III reports 7.57 ns for p=12 versus 7.85 ns for p=8 at n=32 (pp.1, 6).
