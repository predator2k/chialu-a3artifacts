## summary
The document extends Karatsuba multiplication to rectangular FPGA multipliers whose input widths have a large greatest common divisor. Concrete designs use Xilinx DSP blocks as 16×24 unsigned or 17×25 signed multipliers and reduce DSP/LUT use or latency for large multipliers, particularly above 64×64 bits. # p.13, p.18

## families
### recursive_karatsuba  (role: extends)
mechanism: Operands are split into WA-bit and WB-bit chunks. Rectangular subproducts ai bj and ak bℓ can be paired when WAi+WBj=WAk+WBℓ; writing W=gcd(WA,WB), M=WA/W, and N=WB/W identifies the first aligned weights and minimum applicable multiplier dimensions. The implementation uses (ai−ak)(bj−bℓ)+ai bℓ+ak bj so the extra pre-subtraction bit becomes a sign bit accepted by the DSP multiplier. Post-additions are merged into one compressor tree. # p.15, p.17–18
choices:
  split_kind: rectangular  # p.15
  base_multiplier: fpga_dsp_block  # p.13, p.17
new_choices:
  tile_dimensions: 16×24 unsigned / 17×25 signed — widths assigned to one rectangular DSP tile  # p.13, p.17
  rectangular_alignment: WA N = WB M — condition for equal-weight subproducts to be paired  # p.15
slots:
  none
parameters: WA=16, WB=24, W=8, M=2, N=3; synthesized sizes 64×72, 96×96, and 112×120; comparison square sizes 68×68, 102×102, and 119×119  # p.17–19

The method improves large FPGA multipliers above 64×64 bits but is probably not useful for ASIC/software targets. # p.13, p.18

### dsp48_style_slice  (role: instantiates)
mechanism: Each recent Xilinx DSP block provides an 18×25 signed multiplier with a pre-adder and post-adder/accumulator. The selected tiling uses each block as a 16×24 unsigned multiplier; Karatsuba pre-subtractions produce 17×25 signed products, which fit the same embedded multiplier. One operand pre-subtraction uses the DSP pre-adder, while the other uses logic. # p.13, p.17–18
choices:
  mult_shape: 25x18  # p.13
  pre_adder: true  # p.13, p.18
new_choices:
  unsigned_tile_shape: 16×24 — under-used unsigned shape selected to obtain gcd(16,24)=8  # p.15, p.17
slots:
  none
parameters: native multiplication 18×25 signed; selected operation 16×24 unsigned or 17×25 signed  # p.13, p.17

### carry_save_datapath  (role: instantiates)
mechanism: Karatsuba post-additions are accumulated without serial carry propagation. The generated implementations place all post-adders in one FloPoCo compressor tree, so shifted subproducts and correction terms are reduced together. # p.14, p.18

## space_gaps
* `recursive_karatsuba` lacks tile-dimension/GCD choices that express the necessary equal-weight condition for rectangular base multipliers. # p.15
* `recursive_karatsuba.base_multiplier` is an enumeration rather than a component slot that can name `dsp48_style_slice`, although the concrete architecture depends on that block’s multiplier/pre-adder structure. # p.17–18

## open_questions
* The document does not identify the compressor primitives or terminal carry-propagate adder used after the FloPoCo compressor tree. # p.18
* The document does not state whether the external interfaces of all synthesized concrete multipliers are signed or unsigned; signedness is explicit only for the embedded Karatsuba subproducts. # p.17–19
