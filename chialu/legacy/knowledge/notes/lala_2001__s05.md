## summary
The chapter defines totally self-checking two-output checkers and classifies constructions for two-rail, m-out-of-n, Berger, and low-cost residue codes. It settles tree costs/test sets, fault models, several m-out-of-n gate/level comparisons, and the applicability limits of Berger/residue variants.

## families
### two_rail_tree  (role: defines)
mechanism: The checker accepts complementary input pairs and produces complementary outputs if and only if every input pair is complementary. A multilevel realization interconnects checker modules as a tree; invalid output pairs 00/11 indicate either a non-code input or a checker fault.

### berger  (role: taxonomizes)
mechanism: A Type I separable-code checker regenerates the complement of the Berger check field from the information bits and compares regenerated/stored check bits with a totally self-checking two-rail checker. Generator alternatives count information-bit 1s with full-adder modules, represent the Berger code as unions of m-out-of-n codes, partition the code, or recursively combine modular 1s-counters and addition arrays.

  encoding_scheme: B0 | B1 — selects the Berger check-bit encoding used by partitioning/generator variants   # p.128
  information_length: maximal | non_maximal — determines counter/addition cases and encoding assumptions   # p.128, p.132

### popcount_counter_tree  (role: instantiates)

### residue  (role: instantiates)
mechanism: The checker regenerates low-cost residue check bits by partitioning the information word into b-bit groups and combining them with a tree of modulo-(2^b−1) adders. A two-rail comparator checks the regenerated bits against complementary stored check bits.

## new_families
### m_out_of_n_checker  (domain: checker: two-rail / self-checking, closest: two_rail_tree, why_not: The mechanism validates constant-weight code words rather than complementary input pairs.)
mechanism: Two independent output subcircuits classify an input by its number of 1s, producing 01/10 for the required weight and 00/11 for weights below/above it. Variants use two-level threshold logic, cellular arrays, code translators, pass-transistor cells, or inverter-free PLAs; many terminate in a two-rail checker.

## space_gaps
* The checker vocabulary lacks an m_out_of_n_checker family covering constant-weight/two-level/cellular/translator/PLA constructions.   # p.99-p.123
* The berger family lacks a check_bit_generator slot that can accept popcount_counter_tree or an m-out-of-n partition checker.   # p.124-p.128
* The residue modulus choice should permit the parametric form 2^b−1, and generator_style should include a tree of modulo end-around-carry adders.   # p.143

## open_questions
* The scanned formula for the general two-level k-out-of-2k diagnostic test count is read as 2^k, but the superscript is degraded.   # p.99
* The chapter calls the pass-transistor method generalizable to arbitrary m-out-of-2m codes but does not provide the required input-partition construction beyond m=3,4,5,6.   # p.116
