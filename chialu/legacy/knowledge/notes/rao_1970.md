## summary
The document proposes a biresidue code that uses two parallel residue checkers to locate and correct any single-bit error in an arithmetic accumulator. The syndrome also distinguishes errors in either checker from errors in the accumulator.

## families
### multi_residue  (role: proposes)
mechanism: An arithmetic value X is represented by the triple (X, |X|A, |X|B), where A and B are relatively prime moduli. The syndrome S(X,Y,Z)=(|X-Y|A, |X-Z|B) identifies whether an error occurred in the accumulator, checker A, or checker B. Distinct syndrome pairs identify accumulator errors e=±2^j, so a decoder can subtract the identified error from the accumulator output. Two residue checkers execute operations in parallel with the processor and maintain CRA=|X|A and CRB=|X|B. # p.399-p.401

errors_and_checks: A single accumulator error is e=±2^j for j=0,...,n-1, and distinct syndromes provide location/magnitude for correction. # p.399-p.400 An error in checker A produces syndrome (|-e|A,0), while an error in checker B produces (0,|-e|B). # p.399 An accumulator error is undetected when |e|A=|e|B=0. # p.399 A stuck-at-zero or stuck-at-one accumulator fault cannot necessarily be corrected by restoring one result and requires diagnosis/masking. # p.401 False-alarm behavior and aggregate alias rate are UNKNOWN.
conditions: Single-error correction assumes only one component is erroneous and the accumulator error has the form e=±2^j. # p.399 The simple implementation assumes moduli 2^k-1, one's-complement arithmetic, and an n-bit register for which k divides n. # p.399 Unique accumulator-error syndromes require n≤lcm(a,b), with n≤ab for coprime a and b. # p.400 The protected operations are ADD, COMPLEMENT, SHIFT, LOAD ACC., and ROTATE. # p.398, p.400 The residue operations run separately and in parallel with the arithmetic unit, which permits monitoring with practically no loss of computation speed. # p.398
