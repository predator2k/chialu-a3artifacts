## summary
This informative annex recommends programming-environment features for maximum debuggability. The recommendations cover numerical sensitivity, numerical exceptions, NaN histories, and detection of uninitialized floating-point data.

## other_normative
* [recommended] Debuggers should be able to alter attributes governing rounding or exception handling inside subprograms, including subprograms whose source code is unavailable; dynamic modes might provide this capability. # p.66
* [informative] Changing the rounding direction or precision during execution might help identify subprograms that are unusually sensitive to rounding. # p.66
* [recommended] Debuggers should be able to detect and pause execution when a prespecified exception is signaled within a particular subprogram or specified called subprograms. # p.66
* [recommended] The pause should occur soon after the event that precipitated it. # p.66
* [recommended] After the pause, the debugger should be able to continue execution as if the exception had been handled by a specified alternate handler or, otherwise, by the default handler. # p.66
* [informative] An exception pause might not correspond to a well-defined source-code statement boundary, and requiring source-precise pauses might inhibit optimization. # p.66
* [recommended] Debuggers should be able to raise and lower status flags. # p.66
* [recommended] Debuggers should be able to examine every status flag left standing at the end of a subprogram or whole program. # p.66
* [recommended] Each status flag should be implemented as a reference to a detailed record of its origin and history. # p.66
* [recommended] By default, even a subprogram presumed to be debugged should insert at least a reference to its name in a status flag and in the payload of every new quiet NaN produced as a floating-point result of an invalid operation. # p.66
* [recommended] Debuggers should be able to maintain quiet-NaN history tables indexed by NaN payloads. # p.66
* [recommended] Debuggers should be able to pause at every floating-point operation without disrupting the program’s exception-handling logic. # p.66
* [recommended] Debuggers should display source-code lines corresponding to machine instructions whenever possible. # p.66
* [informative] A signaling NaN could reference a record containing a numerical value extended by an exception history, wider exponent, or wider significand. # p.66
* [recommended] Debuggers should be able to cause normally silent bitwise operations such as negate, abs, and copySign to detect signaling NaNs. # p.66
* [recommended] The signaling attribute of signaling NaNs should be globally or locally enabled or disabled without disrupting or being affected by default or alternate handling of other invalid-operation exceptions. # p.66-67
* [recommended] Debuggers should be able to define some or all NaNs as signaling NaNs that signal an exception every time they are used. # p.67
* [recommended] For formats with superfluous bit patterns not generated by arithmetic, including non-canonical significand fields in decimal formats, debuggers should be able to enable signaling-NaN behavior for data containing those patterns. # p.67
* [recommended] Debuggers should be able to initialize uninitialized storage and variables, including heap and common space, to specified bit patterns such as all-zeros or all-ones. # p.67
* [informative] A more helpful debugging environment initializes every floating-point variable, including automatic variables whenever allocated on a stack, to a signaling NaN that references a symbol-table entry describing its source-program origin. # p.67
* [informative] Signaling-NaN initialization is especially useful when the debugger can pause execution after a prespecified exception is signaled or a flag is raised. # p.67

## model_gaps
* The model has no exception flags, flag histories, or references to exception origins. These omissions do not affect bit-exact default results unless the debugging environment uses the recorded state to alter execution. # p.66
* The model has no traps or alternate exception handlers, so it cannot reproduce pause-and-resume behavior under alternate handling. Alternate handling can affect subsequent execution and therefore final bit-exact results. # p.66
* The model has one NaN with no signaling/quiet distinction or payload, so it cannot reproduce payload-indexed histories, origin references, configurable signaling behavior, or signaling-NaN detection by negate/abs/copySign. Payload differences directly affect bit patterns, while signaling behavior can affect control flow. # p.66-67
* The model does not represent debugger-controlled changes to attributes within selected subprogram scopes. Dynamic changes to rounding direction or precision can affect bit-exact results. # p.66
* The model does not represent initialization of storage or variables to diagnostic bit patterns or origin-referencing signaling NaNs. Such initialization can affect results when uninitialized data is used. # p.67
* The model does not represent non-canonical decimal significand fields or configurable signaling behavior for superfluous encodings. This gap affects behavior when those encodings occur. # p.67
