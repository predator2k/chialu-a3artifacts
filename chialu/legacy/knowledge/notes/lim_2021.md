## summary
RLibm generates polynomial elementary-function implementations by constraining each polynomial result to an interval that rounds to the required target value, rather than minimizing approximation error against the real function. An exact rational LP solver generates coefficients while accounting for finite-precision range reduction/output compensation/polynomial evaluation, and exhaustive validation establishes correctly rounded results for the reported Bfloat16/Posit16 functions and fp32 log2. The generated functions generally outperform libraries repurposed from float or double. 

## families
### correct_rounding_strategy  (role: proposes)
mechanism: An MPFR oracle computes RN_T(f(x)) for each target input, and each result defines an H-representable rounding interval. Range reduction maps inputs to reduced inputs, inverse output compensation produces reduced intervals, and intersections combine constraints for inputs sharing a reduced input. An exact rational LP solver finds polynomial coefficients satisfying the intervals. The coefficients are rounded to H, evaluated in H, checked against the original constraints, and regenerated with refined intervals when finite-precision evaluation violates a constraint.

### single_poly  (role: instantiates)
mechanism: Each function uses a polynomial over a range-reduced domain. The LP constraints target reduced rounding intervals rather than the real elementary function, which permits approximation errors larger than a minimax error bound while preserving the final correctly rounded result.

### piecewise_poly  (role: instantiates)
mechanism: When one polynomial cannot satisfy all rounding-interval constraints, the reduced domain is divided and separate interval-constrained polynomials are generated. The reported prototype selects these pieces by trial and error.

### range_reduction  (role: instantiates)
mechanism: Function-specific range reduction maps each target input to a smaller domain, and output compensation reconstructs the result. Inverse output compensation derives reduced rounding intervals, which are tightened until finite-precision compensation in H lies within the original rounding interval.
choices:
  method: cody_waite   # p.24
new_choices:
  output_compensation_constraint: continuous_and_bijective — permits inverse mapping of output intervals   # p.12-16
slots: none
parameters: range reduction/output compensation use double; Bfloat16 logarithms use a modified Cody-Waite reduction; fp32 log2 uses Tang-style range reduction   # p.18-19, p.24-25
results: none
errors_and_checks: Reduced intervals account for numerical error in range reduction and output compensation   # p.9, p.12-16
conditions: Efficient customized range reduction is necessary for low polynomial complexity, good LP conditioning, and avoidance of evaluation overflow   # p.25-26
evidence: Fig. 1, Fig. 9, §§3.1, 4.2-4.3, 5.4.2-5.4.3

## space_gaps
* `single_poly` and `piecewise_poly` lack `rounding_interval_linear_programming` as a coefficient-generation choice   # p.17-18
* `piecewise_poly` lacks a segmentation-selection choice covering the reported `trial_and_error` method   # p.25
* `correct_rounding_strategy` lacks parameters for oracle precision and finite implementation representation H   # p.13, p.18
* `range_reduction` lacks an output-compensation slot/choice and its required invertibility contract   # p.12-16

## open_questions
* The paper delegates exact range-reduction code, output-compensation code, polynomial coefficients, and per-function domain splits to its technical report   # p.19
* The method for systematically selecting constrained samples and piecewise boundaries remains future work   # p.25
* Correctness validation for double without exhaustive enumeration remains open   # p.25
* Constraint generation for multivariate functions such as pow(x,y) remains open   # p.26
