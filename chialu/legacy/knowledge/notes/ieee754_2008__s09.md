## summary
This clause recommends correctly rounded elementary functions/reductions and fixes their domains, special values, and exception behavior. It also requires operations for reading/saving/restoring dynamic modes when a language or implementation supports those modes. Several reduction results, operand formats, and out-of-contract cases remain language-defined or implementation-defined.

## other_normative
* “In this clause the domain of a function is that subset of the affinely extended reals for which the function is well defined.”   # p.52
* The preferred quantum for a conforming function is language-defined, and the previous clauses’ preferred-quantum/inexact specifications do not apply to functions in this clause.   # p.52
* All functions return a quiet NaN when any operand is a NaN, except for the cases listed in 9.2.   # p.52
* Language standards should define as many Table 9.1 functions as are appropriate to the language.   # p.52, p.53
* Interval brackets include the adjacent value, interval parentheses exclude it, Z denotes the integers, and A × B denotes ordered pairs from A and B.   # p.54
* sin/cos/tan/asin/acos/atan/atan2 use radians; sinPi/cosPi/asinPi/acosPi/atanPi/atan2Pi use half-revolutions.   # p.54
* A symmetric function satisfies f(−x) = f(x) for every rounding attribute over its entire domain/range. An antisymmetric function satisfies f(−x) = −f(x) under roundTiesToEven/roundTiesToAway/roundTowardZero. hypot is even in both operands, while atan2/atan2Pi are odd in the first operand.   # p.54
* compound/rootn/pown require n to be a finite integral logBFormat value. If logBFormat is floating-point, behavior for a non-integral or infinite second operand is language-defined.   # p.55
* pow(±0, −∞) is +∞ without exception; pow(±0, +∞) is +0 without exception; finite negative odd exponents produce signed infinity with divideByZero; other finite negative exponents produce +∞ with divideByZero; finite positive odd exponents produce signed zero; other finite positive exponents produce +0.   # p.55
* powr(±0, −∞) is +∞; powr(±0, y) is +∞ with divideByZero for finite y < 0 and +0 for y > 0; powr(+1, y) is 1 for finite y; powr(x, qNaN) is qNaN for x ≥ 0; powr(qNaN, y) is qNaN.   # p.55
* atan2Pi’s zero/infinity cases are exact and signal no exception: atan2Pi(±0, −0) = ±1; atan2Pi(±0, +0) = ±0; atan2Pi(±0, x) = ±1 for x < 0 and ±0 for x > 0; atan2Pi(y, ±0) = −½ for y < 0 and +½ for y > 0; atan2Pi(±y, −∞) = ±1 and atan2Pi(±y, +∞) = ±0 for finite y > 0; atan2Pi(±∞, x) = ±½ for finite x; atan2Pi(±∞, −∞) = ±¾; atan2Pi(±∞, +∞) = ±¼.   # p.56
* atan2’s zero/infinity cases can signal inexact but no other exception: atan2(±0, −0) = ±π; atan2(±0, +0) = ±0; atan2(±0, x) = ±π for x < 0 and ±0 for x > 0; atan2(y, ±0) = −π/2 for y < 0 and +π/2 for y > 0; atan2(±y, −∞) = ±π and atan2(±y, +∞) = ±0 for finite y > 0; atan2(±∞, x) = ±π/2 for finite x; atan2(±∞, −∞) = ±3π/4; atan2(±∞, +∞) = ±π/4.   # p.56
* Non-standard formats with very large precision relative to exponent range might signal additional exceptions, including underflow/overflow for cosPi/log or overflow for tan.   # p.56
* A language standard that defines dynamic binary/decimal rounding-direction modes shall define corresponding get/set operations. Other dynamic attributes require corresponding get/set operations. Use outside the static scope of a dynamic specification is language-defined and may be unspecified.   # p.57
* The required binary operations are `binaryRoundingDirection getBinaryRoundingDirection(void)` and `void setBinaryRoundingDirection(binaryRoundingDirection)`. The required decimal operations are `decimalRoundingDirection getDecimalRoundingDirection(void)` and `void setDecimalRoundingDirection(decimalRoundingDirection)`.   # p.57
* Implementations supporting dynamically specified modes shall provide `saveModes`, `restoreModes`, and `defaultModes` for all dynamic-specifiable modes collectively. Saved `modeGroup` values need only be usable by `restoreModes` in the same program.   # p.57
* Reduction implementations may associate operands in any order and may evaluate in a wider format, so numerical results and exceptions may differ with intermediate precision/evaluation order.   # p.57
* A reduction vector length shall be integral in language-defined integralFormat. A floating-point integralFormat shall have at least sourceFormat’s precision and the same radix. Behavior for a non-integral or negative length is language-defined.   # p.57
* sum/dot/sumSquare/sumAbs shall avoid intermediate overflow/underflow; overflow or underflow is signaled only when the resulting intermediate value produces that final condition.   # p.58
* The vector operands and pr of scaled reductions shall use the same format. The vector length and sf shall have integral values and should use the same integralFormat.   # p.58
* In the absence of NaN/infinity/zero special cases, scaled-reduction pr shall not be affected by overflow or underflow.   # p.58

## model_gaps
* The model has one NaN and cannot distinguish signaling NaNs from quiet NaNs. The gap prevents verification of invalid-operation signaling and can affect bit-exact results in qNaN overrides such as hypot(∞, qNaN), compound(qNaN, 0), pown(qNaN, 0), and pow(+1, qNaN).   # p.52, p.54, p.55
* The model has no exception flags or traps. Default result bits remain verifiable, but required/recommended signaling behavior is not representable.   # p.52, p.53, p.58
* The model does not include roundTiesToAway. Results and the stated antisymmetry guarantee under that rounding direction cannot be covered.   # p.54
* The model does not represent preferred quantum or decimal quantum. This gap does not affect binary result bits, but it prevents checking the language-defined preferred quantum.   # p.52
* The model does not represent dynamic-mode get/set/save/restore/default operations. Per-operation bits can be checked when a rounding mode is supplied explicitly, but dynamic state semantics cannot be checked.   # p.57
* The model does not define logBFormat/integralFormat or language-defined behavior for invalid exponent/vector-length operands. Bit-exact results for those language-defined cases cannot be inferred from this clause.   # p.55, p.57
* The model’s quire is an exact wide scaled integer, while the reductions permit implementation-defined association, wider intermediates, and approximations. A quire result is one permitted strategy only if it satisfies the stated special-value/exception rules; it is not the uniquely required bit result.   # p.57, p.58

## open_questions
* The language or implementation must specify which recommended functions/reductions are provided.   # p.52, p.53, p.57
* The language must specify preferred quantum, logBFormat, integralFormat, and behavior for non-integral/infinite exponents or non-integral/negative vector lengths.   # p.52, p.55, p.57
* The implementation must specify each reduction’s approximation, association order, and intermediate precision before bit-exact expected results can be generated.   # p.57, p.58
* The clause does not define stochastic rounding for these functions, so the model must not infer stochastic behavior from the correctly rounded standard modes.   # p.52
