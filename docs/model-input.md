**145 columns**, of which **12 differ** between the two designs.

## The two designs

They differ in one choice, repeated across the three modes:

```
design A:  bitcount.m0/m1/m2.family = popcount_counter_tree
design B:  bitcount.m0/m1/m2.family = priority_encoder
```

That one choice changes the SET of variables, not only their values. A counter tree has to sum
its counter stages, so it opens a `final_adder` sub-slot; a priority encoder does not:

```
A + core.bitcount.m0.final_adder.family=carry_lookahead  ->  ACCEPTED
B + core.bitcount.m0.final_adder.family=carry_lookahead  ->  REJECTED
      explicit choices are inactive under the selected families:
      ['core.bitcount.m0.final_adder.family']
```

**This is the point of the example.** The configuration is a conditional tree of varying size, and
the vector below has the same 145 columns for both — the sub-slot is folded into the parent
structure's one (area, delay) pair. Whether that `final_adder` is a ripple carry or a carry
lookahead is not representable here at all.

Two caveats that matter more than the encoding:

1. **In the measured corpus that layer never varies.** The sampler enumerated only the depth-3
   `core.<slot>.<index>.family` variables. `int_subword_alu` has 62 free `core.*` variables and the
   designs vary 18; `fp_alu_cmp` has 274 and varies 9. Everything nested, and every pin
   (`chunk_width_bits` is an integer 1..32), sat at its default. So the main argument for a
   variable-size encoder cannot be tested on this data — the variable-size part is a constant.
2. **`EST__delay` is identical in A and B** (1007.8 ps both) because delay is the longest mode path
   and bitcount is not on it — the multiplier at 1208.61 ps holds it. The `ROW__` block still shows
   bitcount moving from 500 ps to 280 ps, so the model can see the difference EXISTS but not
   whether it is on the critical path. That needs topology, and topology is what summing and
   maxing throw away.

## The output

One scalar per model: `syn_delay` or `syn_area`, the yosys+ABC measurement of the whole
`alu_core`. Two separate models, not one with two heads — area and delay behave differently
enough that they were measured to need different treatment, and the literature models them
separately for the same reason.
