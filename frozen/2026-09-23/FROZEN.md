# Frozen measurements, 2026-09-23

Every number below was measured under one flow and re-derived from the raw artifacts by an
independent review (2026-09-23) before this freeze. The files beside this one are those artifacts.
What is frozen is the **measured data**: the reference designs, chiALU's no-model points and
Table B. The **experiment configuration** (the LLM runs' budget, the method definitions, the
ablations) is not frozen; the review found problems in it that must be fixed before any model run
(last section).

## The flow

`+strash;&get -n;&dc2;&dch -f;&nf -C 32 -F 8 -p -D 300;&put;buffer;upsize -D 300;dnsize -D 300;topo;stime`,

buffering pass). Conformance: Verilator against chiALU's reference over the target's verify bundle,
`verify.n_random` 20000 plus the corner set for the reference designs.

## Reproducing

On <host>, from the a3eval root, after `source $CHIALU_HOME/chialu-env.sh` and with
`RAY_ADDRESS=<HEAD_IP>:6395` and `CHIALU=$PWD/3rdparty/chialu`:

```
# the reference designs (synthesis at --tight 300 is built in)
PYTHONPATH=3rdparty/chialu python3 baselines/fpnew/build.py --out runs/fpnew
PYTHONPATH=3rdparty/chialu python3 baselines/transdot/build.py --out runs/transdot
bash baselines/hardfloat/build.sh            # then synth_ppa(runs/hardfloat/alu_core.v, "alu_core", "nangate45", 300)
cd 3rdparty/chialu
for r in fpnew/fpnew_merged_alu_core.sv fpnew/fpnew_parallel_alu_core.sv transdot/transdot_merged_alu_core.sv; do
  PYTHONPATH=. python3 ../../baselines/conform.py --target targets/eval/fp_alu_cmp.yaml --rtl ../../runs/$r --out ../../runs/${r%.sv}.conformance.json
done
PYTHONPATH=. python3 ../../baselines/conform.py --target targets/eval/fp_alu_cmp_hf.yaml --rtl ../../runs/hardfloat/alu_core.v --out ../../runs/hardfloat/conformance_hf.json

# chiALU's no-model points (run/<target> must not exist)
python3 -m chialu.pipeline targets/int_subword_alu.yaml --run-dir run/int_subword_alu --stage calibrate --stage numeric --stage seeds --no-llm
python3 -m chialu.pipeline targets/eval/fp_alu_cmp.yaml --run-dir run/fp_alu_cmp --stage calibrate --stage numeric --stage seeds --no-llm
python3 -m chialu.pipeline targets/eval/fp_alu_cmp_hf.yaml --run-dir run/fp_alu_cmp_hf --stage calibrate --stage numeric --stage seeds --no-llm
python3 -m adir.cli seeds targets/int_subword_alu.best.yaml    # and eval/fp_alu_cmp.best.yaml, eval/fp_alu_cmp_hf.best.yaml
python3 -m adir.cli seeds targets/eval/fp_alu_cmp.hand_chialu.yaml
cd ../..

# Table B (TransDot's DP core needs its combinational patch first; restore the file after)
python3 baselines/transdot/tdot_comb.py
python3 baselines/transdot/build_dp.py --row fp16 fp8 --no-synth --out runs/tableb300/transdot_dp
mv 3rdparty/transdot/src/transdot_fp4_fp8_fp16_fp32_fma.sv.orig 3rdparty/transdot/src/transdot_fp4_fp8_fp16_fp32_fma.sv
python3 baselines/transdot_no_dp/build.py --no-synth --out runs/tableb300/transdot_no_dp
bash baselines/hardfloat_dot/build.sh $PWD/runs/tableb300/hardfloat_dot
python3 sweeps/tableb.py --out runs/tableb300 --clock 300
```

## Limitations of the frozen data (from the review)

* Verification strength differs: the reference designs were checked at `verify.n_random` 20000
  plus corners, the search gates run at 300. Every final front point of every method has to be
  re-checked at 20000 before it enters a table.
* The synthesis database was measured at 1,000 to 6,000 ps, not at 300 ps; the numeric stage, the
  timing source and `prune --best delay` rank by it (delay scale up to 1.58, and `.best` slower than
  the baseline, are consistent with that).
* Wrapper overhead is not separated: the bare FPnew texts keep the whole op set, the second
  `fpnew_top` that FPnew and TransDot instantiate for fcmp's EQ is not reported on its own, and
  TransDot's wrapper drives an 8-bit `flags` against the target's 4.

## Re-checked under the post-audit configuration (2026-09-23, chiALU d39e5af / e8b4d19)

Every no-model chiALU design of the tables was re-evaluated with `verify.n_random` 20000 (the
search's new setting) and `report: true`: the front seeds of int_subword_alu (front_1, front_5),
fp_alu_cmp (front_1, 3, 5) and fp_alu_cmp_hf (front_1, 3, 4, 5), the three `.best` points, the
FPnew hand seed, Table B's two seeds and its four `_td` / `_tdw` points. All are feasible, and every
area and delay equals the frozen value above. The `_td` / `_tdw` run files had carried synthesis
`effort: high` (area and delay then differ, e.g. fp16 `_td` 22,712.1 / 11,157.8); the frozen
table was measured at medium by `sweeps/tableb.py`, which the same RTL reproduces exactly, and the
run files now say medium (chiALU e8b4d19). int_subword_alu's fault rates are sampled from the
bundle, so they move with it (alias 0.0675 -> 0.055, escape_max 0.0134 -> 0.0043, both under the
gate) without any functional mismatch.

## Not frozen: the experiment configuration

The review found these, to fix before any model run (details in the session record):

1. The budget is not equal across methods: an ADIR run is 20 iterations (about 20 candidates), the
   plain loop runs 200 calls; review calls and retries are counted differently; `wall_hours: 12`
   can cut chiALU short.
2. The "generic code evolution" rows keep the library, the review, the declarations and replan.
3. `CHIALU_SYNTH_REPORT=0` in both env files: no ADIR method receives the synthesis report
   feedback, while the plain loop does.
4. The hand-seed experiment's ADIR runs can edit only the `alu_core` wrapper (lines 6655-6844 of
   6,845), the plain loop the whole file.
5. `make_table.py`'s box depends on which archive comes first; pass `--baseline` from
   `pipeline.json` explicitly.
6. The run order in `docs/plan.md` shares run directories across repetitions, starts `adir run`
   without evaluated seeds, and runs `--schemes 0` for one iteration.
7. `vec_dot_acc_cmp.abl_noreplan.yaml` is a no-op (VecDotAcc registers no replan); `noreview`,
   `opfree` and `behavioral` each change a second factor.
